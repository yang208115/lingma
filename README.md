# 灵码

**AI 小说写作工作台**

*从一个念头，到故事的下一页。*

灵码是一款支持本机运行与独立实例部署的 AI 小说写作工作台。把正文、大纲、人物与世界观放在同一个创作空间，让 AI 参与构思、起草与审校，再由作者决定采用哪些内容。

> 「每个尚未写完的故事，都值得拥有下一页。」

[功能一览](#功能一览) · [本机运行](#本机运行) · [开始创作](#开始创作) · [认识栞](#看板娘栞shiori) · [文档索引](docs/README.md)

## 功能一览

- **作品与正文**：长篇、短篇管理，自动保存、版本比较与恢复，导入 Markdown/TXT、导出 TXT。
- **设定与资料**：整理人物、世界观等创作要素，通过引导对话完善作品定位，逐条调整或采用建议。
- **大纲与分章**：从总纲、事件到卷规划与章纲，拆分多章计划，关联正文并查看写作进度。
- **AI 写作助手**：配置模型与接口，通过 `@` 引用资料，结合上下文构思、起草与审校。
- **Skill 管理**：导入通用或项目 Skill，让 Agent 按需读取写作规范、参考资料与附件。
- **多 Agent 编排**：在画布上连接角色与节点，查看产物、编辑重跑、人工放行或开展多轮辩论。
- **会话与运行记录**：管理历史对话，查看节点输出与运行记录，刷新或切页后恢复会话和后台运行。

AI 生成的内容先作为候选展示，经作者确认后才写入正式文档。作品等应用数据保存在运行实例的数据目录中；使用外部模型时，请求中的创作上下文会发送至所配置的模型服务。

## 本机运行

使用 Node **22.22.3**（支持 22.19 起的 22.x）和 **pnpm 11.5.2**。版本约束见 `.node-version` 与 `package.json`。

```sh
pnpm install --frozen-lockfile
cp .env.example .env
pnpm dev
```

浏览器打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。开发服务先构建内部包，再监听四个包的变化；按 Ctrl+C 停止。

首次启动后，进入“模型设置”填写协议、接口地址、模型与密钥，再开始使用 AI 功能。也可先创建作品，手动整理资料与编辑正文。

构建后由 Node 同时提供页面与 API：

```sh
pnpm build
pnpm start
```

打开 [http://127.0.0.1:3000](http://127.0.0.1:3000)。默认仅本机监听；数据默认保存在 `.data/`。环境变量、实例锁、迁移和数据清理见[运行与数据维护](docs/运行与数据维护.md)。服务器部署使用 [Docker 与 Caddy 密码保护](deploy/README.md)。

## 开始创作

1. 在“作品管理”创建长篇或短篇。长篇的基本信息默认从引导对话开始：说出故事想法，AI 整理定位与主题，再逐步追问；设定建议可逐条采用、跳过或编辑。右上角可切换“高级模式”，使用原有分类表单和 AI 助手；两种模式共用设定，对话与未发送输入会保留。已有设定的作品默认沿用高级模式。随后可规划总纲与事件；短篇直接进入正文编辑。
2. 编辑正文或导入 Markdown/TXT 存稿。正文自动保存，可比较历史版本、恢复旧稿并导出 TXT。
3. 在“模型设置”填写协议、接口地址、模型与密钥，在作品右侧助手输入任务。已有模型配置可选择后删除。可用 `@` 引用资料；AI 生成候选经作者确认后才写入正式文档。
4. 按需导入通用或项目 Skill。Agent 根据目录加载所需 Skill 与附件，脚本仅保存、不执行。
5. 在“Agent 角色库”和“工作流模板”配置角色与连线，通过助手的“执行方式”运行。可查看节点输出、编辑、重跑、人工放行及逐条处理审校意见，也支持自由 Agent 图与多轮辩论。

大纲阅读页支持“卷规划 → 多份章纲 → 逐章正文”：点击“拆分为多章章纲”，指定章数（1–30）和所属卷，助手自动选择“分章规划与审校”工作流。确认完整候选后，每份章纲独立保存；卷规划下直接展示分章列表与正文关联进度，也可在“章纲”分类手动新增、编辑和排序。按单章章纲写正文时，参考来源规划与相邻章纲限定情节边界，正文继承章纲所属卷，采用后自动建立关联；已关联正文的章纲可直接打开正文继续编辑。

刷新与切页可恢复会话和后台运行；未保存草稿仍需及时处理，浏览器恢复副本不能替代备份。

详细使用和接口入口见[文档索引](docs/README.md)。

## 看板娘：栞（Shiori）

栞是「页间」——一座存在于所有小说世界之外、收藏着未完成故事的档案馆——的见习管理员，也是灵码的原创看板娘。

她温柔、好奇、认真负责，偶尔有些困倦，也会轻声吐槽。深海蓝贝雷帽、浅蓝书签、银色交叉发夹与星图手册，是她的标志。她会陪作者整理散落的设定、记住尚未收回的伏笔，在卡住时提供几个可能的方向，把故事的选择权交回作者手里。

> 「欢迎回来，作者。」
>
> 「这一页，交给你决定。」

本页立绘为基于栞的角色参考生成的 AI 插画，用于介绍看板娘。

在应用里，栞会出现在作品页的欢迎区、侧栏，以及写作助手与故事引导中，陪你从灵感写到下一页。

## 开发检查

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm build
node scripts/check-browser-build.mjs
pnpm test:agent-smoke
pnpm test:smoke
pnpm exec playwright install chromium
pnpm test:e2e
```

`pnpm check` 汇总类型检查、lint、单元/集成测试和构建；`pnpm format` 应用 Biome 格式化。Playwright、进程冒烟与 Agent 示例运行前需要构建。可选 `pnpm test:skill-git` 验证公开 Git 导入，需要联网。

测试使用合成资料、本地模拟供应商与临时数据目录，说明见[开发样本](fixtures/README.md)。本地模拟验证不代表真实模型的质量和费用；文档中的历史检查结果也不代表当前工作区全部通过。

## 项目结构

| 目录              | 职责                                         |
| ----------------- | -------------------------------------------- |
| `apps/web`        | React + Vite 前端、写作与资料管理、流程画布  |
| `apps/server`     | Hono API、SQLite、附件、模型配置与运行调度   |
| `packages/shared` | Zod schema、领域类型和前后端契约             |
| `packages/agent`  | 自研 Agent 循环、pi-ai 适配与动作/记录器接口 |
| `docs`            | 使用、实施、需求与设计文档                   |
| `fixtures`        | 固定开发与测试样本                           |

项目使用全栈 TypeScript 与 pnpm Workspace。依赖边界由 lint 与浏览器构建检查约束；shared/agent 变化后需要重新构建，开发模式会自动监听。架构与协议见[实施基线与契约](docs/实施基线与契约.md)。

## 当前边界

- 应用没有内置用户账户与权限隔离，面向个人独立实例使用。公网部署需要通过反向代理提供 HTTPS 与认证，见[部署说明](deploy/README.md)。
- 浏览器草稿恢复不能替代数据备份；完整实例备份工具尚未交付。
- Skill 中的脚本仅保存、不执行；Skill 案例比较尚未交付。
- 真实模型的文学质量、延迟和费用取决于所配置的服务，本地模拟测试不代表实际模型表现。

其余待办及验证缺口见[待办与限制](docs/待办与限制.md)。
