# 灵码 · AI 小说写作工作台

全栈 TypeScript、pnpm Workspace。当前已交付 **P00—P05**：小说资料与自动保存、版本比较恢复、导入导出、Skill 管理、自研 Agent loop，以及上下文预览、持久化运行、SSE、写作聊天和人工接受提议。新增可自定义 Agent 角色库与通用多 Agent 编排：流程画布配置模板，在助手选择运行正文、基础信息、世界观、总纲或事件任务，详见[实施说明](docs/MA-通用编排与流程画布实施.md)。真实 pi-ai SDK 已通过本地模拟供应商的完整写作路径验证；环境无供应商配置，真实模型连接与实际计费尚未验证。P06 实验比较、P07 服务器发布与备份尚未实现。

新增功能：[创作要素管理面板与 AI 逐项生成](docs/PRD-创作要素管理与AI生成.md)，涵盖世界观、人物、核心冲突等八类要素；基础面板与 AI 逐项生成已实现，自动传入八类已填写内容，入口为作品内“基本信息”；使用方式和验证限制见 [实施说明](docs/ELM-创作要素实施.md)。

## 页面导航

应用采用左侧全局导航，作品管理首页为 `/projects`；选择作品后可进入写作、大纲、基本信息与项目 Skill。通用 Skill、Agent 角色、工作流模板、模型设置和 Agent 提示词各自独立，导航支持收起与手机抽屉。协作任务统一在写作助手中启动和处理。

页面支持直接访问、刷新和浏览器前进后退，原 `/?project=…&document=…&view=…` 地址自动转换。切页前自动保存正文与大纲；保存失败或冲突时停留原页，手动编辑的配置离开前提示处理。生成任务在后台继续，返回写作页恢复当前会话与运行。详见 [多页面导航实施](docs/NAV-多页面导航实施.md)。

## 本机运行

使用 Node **22.22.3**（支持 22.19 起的 22.x）和 **pnpm 11.5.2**。`packageManager`、`.node-version` 和锁文件固定工具与依赖版本。已安装 pnpm 时直接运行；需要安装时按 [pnpm 官方安装说明](https://pnpm.io/installation)选择方式。

```sh
pnpm install --frozen-lockfile
cp .env.example .env
pnpm dev
```

浏览器打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)，新建作品即可开始编辑或导入存稿。Vite 将 `/api` 代理到后端（默认 3000）。`pnpm dev` 会先构建内部包，再监听四个包的改动。按 Ctrl+C 关闭前后端。

构建后由 Node 同时提供前端和 API，无需 Vite：

```sh
pnpm build
pnpm start
```

打开 [http://127.0.0.1:3000](http://127.0.0.1:3000)。探针为 `/api/v1/health`、`/api/v1/ready`（也提供 `/health`、`/ready`）；就绪返回 200，维护或关闭时 ready 返回 503。迁移失败直接退出，不开放端口。

P01 仅允许 loopback Host 与监听地址，服务器公开部署、HTTPS 和访问认证在 P07 交付。不要把当前服务端口通过反向代理公开。

## 配置与数据

`.env` 始终从仓库根目录加载，环境已提供的变量优先。相对路径也以仓库根目录解析，不受启动时工作目录影响。Vite 只读取 HOST/PORT 用于代理，不把 `.env` 注入客户端。

| 变量                | 默认值        | 说明                             |
| ------------------- | ------------- | -------------------------------- |
| HOST                | 127.0.0.1     | 仅允许 127.0.0.1、localhost、::1 |
| PORT                | 3000          | 1—65535                          |
| DATA_DIR            | .data         | 实例私有目录，不能与静态目录重叠 |
| TEMP_DIR            | DATA_DIR/tmp  | 导入暂存；可配置独立私有目录     |
| WEB_DIST_DIR        | apps/web/dist | 构建后的前端目录                 |
| SHUTDOWN_TIMEOUT_MS | 10000         | 优雅关闭期限，100—60000ms        |

```text
.data/
  .instance.lock/          # 进程独占心跳锁
  workbench.sqlite        # 作品/资料/Skill/运行/提议/事件及迁移记录
  workbench.sqlite-wal    # SQLite 运行时文件，不能忽略它直接复制主库做备份
  workbench.sqlite-shm
  blobs/ab/<sha256>       # 不可变附件
  tmp/
  backups/                # 仅建立目录，备份工具在 P07
```

数据目录仅由一个进程使用，不支持网络共享文件系统。重复启动会被拒绝；正常退出释放锁，异常退出的锁最多等待约 30 秒过期。不删除活跃实例的锁。数据库、真实环境文件及附件目录均由 `.gitignore` 排除。

迁移位于 `apps/server/src/db/migrations/`，当前 schemaVersion=20；P05 的 `0004-writing.sql` 增加运行、配置、会话、提议与事件，`0005-writing-citations.sql` 扩展逐轮引用唯一约束，`0006-agent-prompt.sql` 保存全局 Agent 提示词，`0007-run-thinking.sql` 保存逐轮思考内容并恢复旧记录已保存的可显示文本，`0008-workflows.sql` 和 `0009-agent-trial-versions.sql` 增加角色、模板、工作流及未发布角色试运行，`0018-workflow-session-history.sql` 为通用编排会话历史增加索引，`0019-skill-scopes.sql` 区分通用与项目 Skill，`0020-workflow-reset.sql` 随编排重设计清空旧模板与运行记录（保留角色库、模型配置与全部文档）；保留已有作品及 Skill 历史，并保持已应用迁移的 checksum 不变。启动自动校验迁移版本及 checksum，应用未执行迁移；修改已执行迁移或使用未知新版本数据库会拒绝启动。升级发布、回退及一致性备份工具归 P07，当前不提供数据库降级。

### 清理数据并保留模型信息

```sh
pnpm data:clean                 # 只预览表记录数和待移除目录
# 先停止 pnpm dev / pnpm start，再执行：
pnpm data:clean --execute
```

保留模型设置（`provider_configs`）、加密 API 密钥（`credentials.enc` / `credentials.key`）、数据库结构与迁移记录，`.env` 保持原样。清空其余业务表，包括作品、正文和历史、聊天、运行记录、Skill、Agent 角色、工作流、全局提示词及模型连接检查历史，同时删除附件、旧备份和导入临时文件。自定义 `TEMP_DIR` 仅清理 `novel-imports` 和 `skill-git-*`，其余文件保留；浏览器本地草稿和界面偏好不属于服务端清理范围。

执行时使用与服务相同的实例锁，拒绝清理正在运行的数据目录。删除前在数据目录旁创建 `<数据目录名>.backup-*`，保存 SQLite 一致性快照、数据目录内其他文件及外置导入暂存。备份失败时不删除原数据。备份包含清理前的数据与密钥，请妥善保管；确认无需恢复后可自行移除。恢复时停止服务，以备份内容替换数据目录；如使用外置暂存，将备份中的 `__external_temp__` 内容还原到 `TEMP_DIR`。脚本读取根目录 `.env`，也支持环境变量覆盖 `DATA_DIR` / `TEMP_DIR`。

## 小说工作区

1. 新建/选择作品；通过“新建文档”建立正文、总纲、章纲和人物。章纲必须选择同一作品中的正文。
2. 在“管理目录”创建卷、修改标题、调整顺序和章节归卷；目录修改检查结构版本。移除卷将正文归回未分卷；删除正文同时软删除其章纲，历史仍保留，当前没有回收站界面。
3. 编辑正文约 800ms 后自动保存，可点“立即保存”。人物等字段可填写“版本化元数据”的 JSON 对象，与正文一起保留历史。编辑器采用原生 Markdown 文本区，保留浏览器基本编辑能力和 UTF-16 选区；右侧可发起续写、选中改写及审校聊天。
4. 每份文档的保存请求串行执行，保存中继续输入会接着提交；切章不销毁待保存队列。失败保留草稿并支持重试；冲突展示服务器版本与本地草稿的文本/元数据差异，可在编辑区合并后保存，或明确放弃本地稿。
5. 未保存草稿额外放在本标签页 sessionStorage，刷新后会找回当前作品的待保存文档；存储不可用时提示保持页面打开。它不代替服务端保存或备份，关闭标签页可能失去这些浏览器恢复副本；存在未保存内容时浏览器会提示离开确认。
6. “版本历史”比较任意两个已加载版本的正文与元数据，支持继续加载旧版本；恢复总是新增版本。名称/排序由独立目录版本管理，不随正文历史恢复。
7. 导入先上传预览，可修改章节标题/正文、增删和前移预览项，再确认写入。首章前的文本、重复标题和空章均保留并提示。UTF-8 严格解码失败时可选择 GB18030/GBK、Big5 或 UTF-16 LE；不自动用乱码入库。预览在私有临时目录保留 24 小时有效性，暂不自动回收过期文件。
8. 导出当前章节或整部作品为 UTF-8 TXT，先完成相关待保存草稿；冲突/失败未处理时不开始下载。整书按未分卷、卷顺序及各卷章顺序输出，排除大纲、人物、聊天及运行记录。

当前实现限制：单文件 8 MiB、导入总文本 400 万字符、单文档 100 万字符、单次导入 1000 项、文档元数据 64Ki 字符、HTTP 请求体 12 MiB。拆章规则仅辅助识别常见中文章回/Chapter/Markdown 二级以上标题；特殊排版应人工修正。详见 [P02 实施与接口](docs/P02-小说工作区实施.md)。

## Skill 管理

1. 左侧“创作工具 → 通用 Skill”管理所有项目共享的方法；“当前作品 → 项目 Skill”管理仅所属项目可用的规则。已有 Skill 默认归入通用类，详情中的“Skill 归属”可切换为通用或指定项目，保留版本与附件。写作助手自动获得通用 Skill 和当前项目 Skill，Agent 角色按所选版本使用，跨项目指定版本会被拒绝。
2. 两类页面均可导入单个 SKILL.md、完整 Skill 目录或包含多个 Skill 的父目录，导入内容归属当前页面。父目录自动按各个 SKILL.md 所在目录拆分，每项完成后再导入下一项，分别保留附件和结果；大小限制按每个 Skill 计算。Git 导入填写公开 HTTPS 仓库及子目录。单文件缺少关联附件时明确提示。
3. 查看格式化正文、未知 front matter 元数据、关联文件及示例；脚本作为文件保存，不执行。原始 HTML 和外部图片不渲染，不支持的二进制附件可下载。
4. 入口源码显式保存为新版本。失败保留编辑，冲突后比较并手动合并；切换或关闭时提示未保存内容。Skill 编辑目前没有刷新恢复保证。
5. 版本选择与对照同时展示入口、附件和来源差异，`skillVersionId` 可复制。Git 更新或重新上传完整本地目录创建新版本，不改源文件、不推送、不改旧历史。
6. 导入任务与结果 ID 持久化，各类页面可查看所属范围最近 50 个任务；正常关闭取消任务，重启后上次未完成任务标为中断，可重新导入。

限制：入口 256 KiB、单文件 2 MiB、最多 200 个文件/16 MiB、路径 16 层；Git 全部下载响应体 32 MiB/60 秒，仅公网 HTTPS 443，拒绝凭据、重定向、符号链接及子模块。使用默认分支 HEAD，不支持私有认证、自选分支/标签或 LFS 实体下载。详细 API、格式、安全边界和验证记录见 [P03 实施说明](docs/P03-Skill管理实施.md)。

## Agent 核心

`packages/agent` 提供可切换 Fake/pi-ai 的自研循环、固定动作注册表、取消/超时/限额、完整轮次检查点和用量汇总。pi-ai 1.5.0 支持 OpenAI Completions、Responses 与 Anthropic Messages 三种协议，凭据和动作实现通过接口注入。所有增量仅用于展示，完整响应验证后按顺序执行动作；未知用量保持 null，不同币种分别累计。

构建后运行 `pnpm test:agent-smoke`，离线完成“读取合成人物资料→生成候选”两轮示例，不使用密钥或网络。核心记录器/处理器契约及限制见 [P04 实施说明](docs/P04-Agent循环实施.md)。

## AI 写作与聊天

左侧“Agent 提示词”可编辑所有作品共用的系统提示词，保存后用于新任务，刷新或重启后保留；“恢复默认”先恢复编辑内容，再保存生效。可用 Skill 目录自动附加。提示词变更后须重新预览，已有运行及其重试沿用原提示词。

工作台采用深色主题。右侧输入区整合模型、任务用途和发送操作，支持 Ctrl / ⌘ + Enter 发送；生成时发送按钮变为停止按钮。顶部历史图标打开会话与运行记录，输入区设置图标打开资料权限；思考内容展开后独立滚动。

1. 左侧“模型设置”配置协议、接口 URL、模型 ID 和上下文/输出上限。支持推理的模型可勾选“启用模型推理”，以中等强度请求推理；可见思考文本或摘要是否返回由接口决定。API 密钥可直接在界面填写并保存，服务端加密保存在实例目录，重新启动后仍可使用；已有环境变量引用配置仍兼容。远程必须 HTTPS，本机模型可使用无密钥 HTTP。
2. 在正文旁选择模型并填写任务；改写时先选中文字。已导入 Skill 的名称和描述自动进入提示词，由 Agent 判断并调用 `load_skill` 加载全文、`read_skill_file` 按需读取附件，可以使用多个 Skill；没有 Skill 也能运行。保存并预览上下文，调整允许资料、固定全文及未来章纲授权，再开始执行。固定内容超预算时要求调整，不静默裁剪。
3. 中间固定显示正文编辑器，右侧 AI 聊天栏独立滚动，输入框保留在底部；发送后自动预览上下文并执行，回复与提议显示在对话中。“思考过程”默认折叠，按轮次实时显示模型返回的可见推理文本或摘要，刷新后仍保留；模型未返回时明确提示。思考内容独立于候选和正文。会话、运行记录及资料权限可展开查看，还可取消或从完整检查点显式重试。每轮模型超时会自动重试最多 5 次，并显示次数；取消、总时限和预算仍可提前终止。断开浏览器不取消运行，重启遗留任务标记中断。
4. 模型候选独立显示；比较提议后接受才新增正式版本。旧基准冲突保留新稿与候选，重复接受不重复写入。审校默认只读，Skill 实验用途禁止正式文档提议。

检查连接是显式模型请求（最多 16 输出 Token），配置真实供应商后可能收费。未知 Token/费用明确标为未知，不支持金额硬预算。当前全局同时执行 1 个任务、活跃队列最多 32；同作品写作和同会话运行有占用限制。完整 API、估算规则、SSE 和验证边界见 [P05 实施说明](docs/P05-写作流程实施.md)。

## 多 Agent 协作写作

左侧“Agent 角色库”“工作流模板”分别管理角色和流程配置。协作运行统一通过写作助手的“执行方式”选择模板后发送任务，在对话卡片中查看每个节点的返回内容、编辑产物、手动放行、逐条采纳审校意见并采用结果。旧 `/projects/:projectId/workflows` 地址兼容跳转到写作工作区，带 `run` 的旧链接打开相应运行及所属会话。用户可从空白创建或复制 Agent，自定义提示词、模型、Skill、工具权限和资料类型；角色发布后可替换模板中的策划、正文、审校或修订角色，也可新增对白润色、伏笔审校等阶段。

默认流程：章纲策划 → 作者确认 → 正文初稿 → 一致性与叙事审校 → 必要时修订并复审 → 作者接受最终稿。角色、模型、资料和产物按版本冻结；流程共用原全局执行队列，支持暂停、取消、失败重试、重启后显式恢复及 SSE 重连。未发布角色可对当前章节试运行，不修改正式正文。

节点提交产物缺字段时，服务端保留原内容并列出全部校验问题，模型通过补全工具只输出指定字段，合并后再次完整校验。补全草稿随运行保存，重启或从检查点恢复后可继续补齐；通过校验前不会生成正式候选，已有有效字段不能被补全覆盖。结构补齐不代替事实核验，未知资料需标明待确认。旧运行沿用冻结的工具权限。

基础信息缺少整类条目时也会列出缺失分类，保留已通过校验的条目，允许通过原提交工具分批补齐，兼容没有补全工具的旧运行。字段补齐后仍缺分类时继续保存并提示；补齐全部所选分类后再完成整体校验。业务校验失败会向模型返回具体原因，不再误报为内部异常。

作者可编辑任意节点产物，下游结果标记为已被替代并重新审校。引用资料变化时需明确沿用快照或刷新复审；正文基准变化时先提供合并后的完整稿。所有最终提议仍由作者接受后写入新版本。自动修订采用开关，开启后持续修订并复审，不设工作流调用次数或修订次数上限；上下文仍受模型容量约束，不提供金额硬预算。详细接口、恢复语义及限制见 [多 Agent 实施说明](docs/MA-多Agent工作流实施.md)，设计见 [工作流方案](docs/多Agent小说创作工作流方案.md)。编排已按[重设计](docs/多Agent编排重设计.md)改为 Markdown 产物的固定阶段流水线：画布仍由连线定义依赖，每个节点可选自动或手动放行，审校意见逐条采纳，修订只处理被采纳的条目；已实现 S1（引擎与正文），S2—S4 见该文档。

通用编排已支持在助手输入区选择模板运行正文、基础信息、世界观、故事总纲与事件规划。基本信息页 AI 助手默认使用“基础信息构建与审校”，同一套编排覆盖主题、世界、人物、冲突和文风，支持整套或当前分类完善，结果按分类审阅和采用；基础信息与大纲不要求已有章节。模板默认在节点画布编辑，支持拖动、连线、节点配置和布局恢复；实际执行仍在本机后端。参见[实施说明](docs/MA-通用编排与流程画布实施.md)及[产品设计](docs/通用创作编排与助手入口设计.md)。

## 开发与检查

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm build
node scripts/check-browser-build.mjs
pnpm test:agent-smoke
pnpm test:smoke
pnpm exec playwright install chromium
pnpm test:e2e
# 可选：真实公开 Git 导入/编辑/更新验证（联网，先完成 build）
pnpm test:skill-git
```

`pnpm check` 汇总类型/lint/单元集成测试/构建；`pnpm format` 应用 Biome 格式化。Playwright 与 Agent 示例使用已构建产物，运行前先 `pnpm build`；浏览器测试、进程冒烟均创建临时数据目录并在退出时清理。已有测试与新增验证范围见各模块实施说明；创作要素的浏览器完整路径尚未复验，不调用付费供应商；写作浏览器测试使用真实 pi-ai SDK 和本地 HTTP 模拟接口，并实际切断 SSE 验证原生重连。CI 从锁文件安装后执行类型、lint、测试、构建、浏览器包检查、Agent 离线示例、进程冒烟及 Chromium E2E。

`better-sqlite3` 使用平台原生二进制，当前已在 Linux x64 / Node 22 验证；其他发布目标在 P07 验证。pnpm 构建脚本仅按 `pnpm-workspace.yaml` 的 allowBuilds 清单运行；本阶段未使用的供应商可选构建脚本被显式禁用。

## 模块边界
