# 自由 Agent 图与多轮辩论

工作流模板页默认选中“多 Agent 辩论”。每个可编辑节点绑定一个已发布 Agent，可新建空白工作流、添加任意角色、拖动节点和连线。节点不再要求依次经过生成、审校或系统汇总；原有审校模板仍按原规则执行，可通过“转为自由 Agent 图”转换草稿，发布后才影响新任务。

## 配置与运行

1. 选择“新建工作流”，或复制“多 Agent 辩论”。
2. 用“添加 Agent 节点”加入角色，点击节点配置任务／立场、参与时机、人工放行及最终输出。
3. 左右连接点传递本轮发言：下游等待上游完成后接收其输出。每个节点只收到连入节点的发言，不会收到无关分支的内容。
4. 上下连接点传递下一轮反馈，显示为黄色虚线。普通连线形成回路时自动改为下一轮反馈。首轮忽略反馈边、独立发言；后续轮次接收相连 Agent 上一轮的发言，同时记住自身上一轮的论点。
5. 设置 1–20 轮，选择汇总 Agent 为“辩论结束后汇总”及最终输出，并将辩手普通连线接入汇总者。汇总者只在最后一轮运行，收到相连分支的完整讨论记录，保留分歧而不强制达成共识。
6. 保存并发布。在作品的写作助手“执行方式”中选择该模板，再发送议题。发言按轮次保留，支持暂停、取消、人工放行、重跑和编辑产物。

默认示例包含正方、反方、主持三个独立 Agent，正反方通过双向反馈交换观点，3 轮后主持汇总。逻辑上的独立发言仍共用应用的模型执行队列，不代表同时请求供应商。

“讨论 / 辩论”用途将结论保存在运行记录中，确认结束不会新增或修改正式小说资料。也可将自由图用途设为正文、世界观或其他创作任务，由最终输出 Agent 按相应用途生成候选，经过作者确认后入稿。角色指定的模型、工具、Skill 与授权资料继续生效。

## 实现约定

模板 JSON 的 `executionMode: "graph"` 启用自由图；省略时保留旧审校语义。`steps` 的 `stage` 为 `agent`，`dependsOn` 为本轮依赖，`feedbackFrom` 为上轮输入，`instructions` 为节点立场，`runWhen: "after_rounds"` 标识收尾节点，`outputNodeKey` 指定最终结果，`maxRounds` 控制轮数。无需数据库迁移，配置和发言沿用 JSON 快照存储。

执行器将反馈图展开为有限轮次的依赖图，不允许同轮死循环，也不允许收尾节点反向阻塞辩论。每轮输入与节点运行记录均持久化。重跑会重新执行真实依赖的后续节点，保留旧产物；未连接的节点不会被注入上下文。

一次运行继续使用启动时冻结的资料和角色版本。需要最新资料时启动新辩论。实际供应商的输出质量与费用需由实际模型运行评估；测试使用模拟适配器验证传话、轮次、收尾、人工放行、取消和重跑，不会调用付费模型。

## 在审校流程里嵌入整场辩论

原有模板可使用画布工具栏「＋ 多 Agent 辩论」或「添加节点 → 多 Agent 辩论」。无需转换为自由图。默认插到最终生成节点与下游之间；选中节点时插在该节点后，选中普通连线时只插入该条连线。

辩论对外是一张节点卡片：上游内容进入，汇总结论输出。右侧可配置议题、2–8 位辩手的已发布 Agent 与独立立场、1–20 轮交锋，以及汇总 Agent。默认正反两方、3 轮、主持汇总。汇总可自动放行或等待人工确认。

首轮各自读取上游材料；后续每轮读取全部参与者的上一轮发言。汇总 Agent 接收全部轮次和原始上游材料。审校同时读取原稿与连入的辩论结论；讨论内容不会替换正式候选稿。运行面板将内部发言折叠在辩论节点下，支持查看、编辑、重跑和取消。

修订产生新稿时，位于生成节点下游的辩论会针对新稿重新进行，再交给审校。重跑或编辑已有发言会使后续相关发言、汇总与下游节点重新执行，历史产物仍保留。参与者使用启动时冻结的 Agent、模型与资料快照；需要更新资料时请开始新流程。模型调用仍共用全局队列依次执行。
