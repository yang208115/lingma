## 2. 数据归属和存储边界

Agent 提示词设置通过后续迁移 `0006-agent-prompt.sql` 保存，该迁移引入时 schemaVersion=6，当前包含 MA 迁移的数据库版本为 9。全局提示词可从顶部编辑、保存及恢复默认；新任务固定正文和修订号，变更使旧预览失效，已有运行及重试继续使用原快照。

作品、卷章、大纲、人物、不可变正文版本、Skill 入口及版本清单保存在实例 SQLite 中；附件按 SHA-256 放在 `DATA_DIR/blobs`。P05 的运行、实际输入、检查点、提议、会话、事件及非敏感配置也已入库，仍属于该实例；实例访问者共享全部数据，不声称有账号隔离。

浏览器只持有界面状态及待保存草稿，不是权威数据库。P02/P03 已开放小说及 Skill 业务写入，统一通过 server 服务的短事务和 `MaintenanceGate`。sessionStorage 用于本标签页草稿恢复及当前会话/运行定位，不代表离线权威库或跨设备同步。`shared` 不依赖文件系统或数据库，`agent` 仅通过注入接口访问资料和提议服务。

密钥不属于正文、Skill、测试案例、事件或运行快照。模型设置现支持直接填写 API 密钥，服务端以 AES-256-GCM 加密保存，配置与快照只存 local:引用；兼容已有 env:变量名引用。API 不回显密钥，备份须排除 credentials.key 和 credentials.enc。当前 `.env.example` 和合成样本没有可用凭据。

目录锁采用 `proper-lockfile` 的原子目录创建和心跳；更新间隔 10 秒、过期时间 30 秒，不允许多个进程/容器/机器共同访问一个数据目录。异常退出可能需要等待锁过期；不能手动删除活跃实例的锁。锁被破坏后停止写入并关闭进程。SQLite 不放网络文件系统，长时间阻塞事件循环的工作不得进入请求线程。

附件先在 hash 目标同目录写临时文件并 flush，再用硬链接原子发布，不覆盖已存在文件；读取校验 hash，发布失败不会创建数据库引用。P03 的导入服务必须先完成附件发布，再提交版本和 manifest；孤立 blob 可保留，首版不自动回收。

维护时先阻止新的写入并等待在途写入结束，再执行维护回调；回调失败也释放门闩。关闭时停止接收请求、执行注入的取消/收束钩子、等待写入结束、关闭数据库，最后释放目录锁。P07 备份及 P05 运行管理器复用此接口。

## 3. 一次任务的行为

1. 作者保存本地编辑，选择模型、任务用途、目标和资料；server 把 Skill 名称、描述及版本目录加入系统提示词，组装不可变版本输入并校验预览 hash，在创建短事务复核目标与模型配置，固定快照及允许资料清单。Agent 通过工具按需加载 Skill，不要求作者选择 Skill。
2. 循环核心检查取消和预算，发起一次模型请求；完整响应到齐前不执行动作。
3. 有动作时按顺序校验名称、参数、清单权限及基准版本；返回带 call ID 的结果。资料只读冻结版本，修改仅建立 `staged` 提议。
4. 一轮完整提交后提议转 `pending`，写检查点及事件；有动作则发起下一轮，无动作正常响应则结束。轮数、动作数、期限、取消、错误、截断分别保留停止原因。
5. 运行终态与提议状态分开。作者稍后接受提议，在短事务内检查当前版本、创建新版本并记录应用结果；基准过时返回冲突，重复接受返回同一个版本。
6. 手动重试创建新 run，保持原记录，复用最近完整检查点及已完成动作结果；不把终态改回 running。启动恢复将遗留非终态标记 `interrupted`。

P04 已实现以上循环及动作/记录器注入接口，并通过假模型和真实 SDK 的模拟流验证。P05 已接通创建运行、实际小说资料、原子轮次/终态、重试关联、提议接受、启动恢复及写作界面。生产使用 SQLite 记录器；MemoryLoopRecorder 仅用于离线测试/连接检查。真实 SDK 经本机 HTTP 模拟供应商验证，真实供应商未验证。

HTTP 前缀 `/api/v1`；P02 已提供作品、目录、文档/版本、导入和导出端点；P03 已提供 Skill 导入/编辑/历史、任务状态及 manifest 附件读取；P04 核心无 HTTP 依赖；P05 已提供配置/检查、上下文、会话/消息、运行/SSE 和提议端点。readiness 为 503 时禁止业务写入；启动迁移失败直接退出，不监听端口，因此也不会错误返回 ready。小说与 Skill 的具体输入以 shared/novel.ts、shared/skill.ts 和各阶段接口说明为准。

### 4.2 事件

所有事件都包含 schemaVersion=1、runId、seq(正整数)、type。turnIndex 从 **0** 起；seq 从 **1** 起。SSE event 字段等于 JSON type，id 等于 seq 的十进制字符串。

| type                 | 其他字段                                                         |
| -------------------- | ---------------------------------------------------------------- |
| run.started          | modelId、startedAt                                               |
| turn.started         | turnIndex                                                        |
| text.delta           | turnIndex、messageId、text                                       |
| tool.arguments.delta | turnIndex、callIndex、delta；仅展示参数分片                      |
| tool.started         | turnIndex、executionId、callId、name                             |
| tool.completed       | turnIndex、executionId、callId、resultSummary、isError           |
| proposal.created     | turnIndex、proposalId、targetDocumentId                          |
| turn.completed       | turnIndex、usage                                                 |
| run.finished         | status(终态)、stopReason、usage(known/complete)、outputMessageId |

事件先落库再发布；重连优先 Last-Event-ID，其次 after；过期返回 410，客户端先取快照。未知类型可跳过，不兼容版本提示刷新。P04 通过记录器产出事件，proposal.created/turn.completed 与检查点组成 commitTurn 原子批次；tool.started.name 可记录未知动作名而不授权其执行。P05 已实现 SSE 持久化与重放；50ms/约 4096 字符合批，seq 严格递增但可有间隔。有效 Last-Event-ID 优先于旧 after；非法游标 400，过期 410，前端重新取快照。实际浏览器断线重连已验证。

### 4.3 幂等

创建运行、创建重试、创建候选提议和接受提议要求 `Idempotency-Key`（8—128 个 ASCII 字母、数字、下划线或连字符）。scope 由实例、操作和目标共同确定，不能跨操作复用结果。服务端对规范化且通过 schema 校验的请求计算 SHA-256；字段顺序采用递归键排序，数组顺序保留。

同 scope/key/hash 返回首次状态码与响应；同 scope/key 不同 hash 返回 409 IDEMPOTENCY_CONFLICT。业务写入与幂等结果同事务提交；失败回滚不占用 key，重复接受同一提议即使换 key 也返回原 acceptedVersionId。记录至少保留至相关对象被清理。P01 定义语义与 key schema，P05 已实现事务内持久化。

## 多 Agent 增量契约

新增可自定义 Agent 角色库、角色与模板发布版本、阶段列表配置、结构化产物、持久化父子运行和作者决策，MA 功能对应迁移 0008、0009。内置角色是可复制预设，名称和数量不写死；能力及产物契约由 shared schema 定义。子运行与角色试运行共用全局单模型队列，最终提议由作者接受后写入，已有单 Agent 功能继续可用。
