# 创作要素管理与 AI 生成实施说明

日期：2026-11-04  
最新调整（2026-11-04）：移除整套一键生成，所有新任务只允许一个要素分类；无论生成或重生成哪一类，自动传入当前作品八类中全部已填写的最新内容（含已保存草稿），空白项跳过。归档条目继续保留在历史中。

关联：[需求方案](./PRD-创作要素管理与AI生成.md)

## 已实现范围

作品内增加“写作 / 创作要素”切换。面板覆盖故事定位与主题、世界观、人物与关系、核心冲突、情节主线、时间线、伏笔与悬念、叙事与文风八类要素，提供分类总览、搜索、状态/标签筛选、字段表单、关联选择、反向引用、复制、归档与恢复、版本历史和草稿恢复。人物与主线沿用原有文档 ID；补充字段存于版本化元数据的 `element` 命名空间，保留旧正文及未知元数据。

面板采用显式“保存草稿”，未保存内容在当前标签页的 sessionStorage 中保留；浏览器恢复不可用时提示作者。正文原有自动保存机制继续使用。字段及整项可锁定 AI 修改，作者手动编辑仍由自己决定。保存、确认与归档分别处理，已确认版本通过独立指针保存；后续编辑及历史恢复形成待确认的新版本。

AI 支持单类生成、指定条目补全、替代候选、已有资料提取及单独重生成待审候选。不需要先创建章节或导入 Skill。每个新任务只生成所选的一类，人物、事件或伏笔在该分类内仍可有多个条目；总览不默认选择世界观。原有整套任务的记录和候选可查看，但不再继续批量生成。

生成设置及生成任务集中在最右侧的独立侧栏，侧栏明确显示当前生成目标。历史任务和待审候选按左侧分类筛选，切换分类时清空候选选择及批量勾选；从总览打开候选时同步选中它所属的分类。请求显式标注目标分类，可修改条目索引仅列出本分类；八类已填写内容仍完整传入参考上下文。服务端拒绝与目标分类不符的模型候选。

长篇准备引导条改为紧凑的两行说明，步骤、已填写数与保存提示集中显示，缩短开始写作按钮。右侧生成面板在桌面端加宽至 360—480px，并按窗口宽度调整；表单控件充满可用宽度，生成和审阅按钮使用网格排列，候选标题与状态分行显示，窄屏仍纵向排列。

长篇准备页的详情顶部新增同类要素切换栏：人物分类显示“角色列表”、角色数、姓名与采用状态，点击姓名直接查看其他角色，当前角色高亮。其他分类同样可切换多条资料。列表只显示未归档条目，未保存改稿时提示先保存再切换；详情滚动时列表保留在顶部。普通管理页继续使用原条目列表。按用户要求未运行测试。

候选采用入口改为逐条“采用 / 拒绝”，详情区也可直接处理当前候选；仅在存在多条待采用候选时显示全选与批量操作，所有操作只取当前任务、当前分类且仍待采用的候选。采用成功后自动打开已入库的正式条目，已确认的当前版本不再提供重复确认操作。已采用和已拒绝候选展示状态标签，不显示失效复选框；已采用条目点击可查看正式资料。未保存改稿或正在生成时禁用采用/拒绝并明确提示。相同候选与修订号的同一决策复用幂等键，失败后刷新状态，避免把处理完成的候选重复提交。此次布局和采用流程调整按用户要求未运行测试。

执行复用现有 pi-ai、自研 Agent loop、全局队列、运行记录及用量统计。任务冻结模型配置、提示词和资料版本。生成上下文自动覆盖八类已填写要素的最新保存版本，包括草稿，不再提供关闭草稿的开关；纯名称占位、空摘要及空白字段不算已填写。正文和章纲仍作为作者勾选的额外资料。模型上下文超限时明确报错，不静默省略某类设定。单独重生成候选时重新读取全部已填写要素；失败重试沿用任务启动时的完整快照。阶段通过最终 JSON 输出提交候选，服务端校验 schema、类型、来源、临时关联与生成范围；不调用模型直接写正式资料。格式自动修复全任务最多一次。上限或后续阶段失败保留已有完整候选，支持取消和显式重试；重试追加一次有限尝试额度，不重跑已经完成的阶段。

候选可由作者编辑、拒绝、逐项或批量确认。批量接受统一检查依赖和目标基准，在一个事务中建立正式条目、替换临时 ID、保存版本并确认；任一冲突使整批回滚。重复请求通过幂等键复用结果。单独重生成保留候选 ID、增加修订号，并保留作者锁定字段；已接受候选不能原地重生成。

## 写作联动与状态

新写作默认采用已确认版本，未确认和归档要素不自动加入；显式选择资料版本可授权草稿。未来规划沿用并扩展 `allowFutureOutline` 控制，界面文案改为“允许未来规划（章纲、事件、伏笔等）”。确认未来事件不改变其内容性质。模型可以读取某项秘密，不代表正文中的每个人物都知情。

现有角色的 `contextKinds` 保持原样，角色编辑器增加八类要素对应的选项和“启用全部创作要素资料”按钮，保存并发布新角色版本后生效。作者显式“刷新资料并复审”时，工作流采用已经授权文档的最新版本，包括作者新草稿；不会扩大到其他作品。

任务持久化阶段进度、模型尝试、候选和审阅状态，提供 SSE 游标重放与快照补读。关闭服务或重启后保留记录，需要显式重试；候选完成不等于正式入库。

## 数据与接口

迁移 `0010-creation-elements.sql` 将 schemaVersion 升至 10，扩展六个文档类型，新增确认指针、要素任务、尝试、候选与事件表。迁移不修改已应用文件；SQLite 文档表重建时在事务外临时关闭外键执行，在事务提交前验证完整性，最终恢复外键检查。旧人物和总纲当前版本作为确认基线，历史内容和文档身份不变。

接口均使用 `/api/v1` 前缀：

| 接口                                             | 用途                             |
| ------------------------------------------------ | -------------------------------- |
| `GET/POST /projects/:id/elements`                | 查询与创建要素                   |
| `GET/PUT /elements/:id`                          | 读取或保存字段与说明             |
| `POST /documents/:id/element-confirmations`      | 确认指定当前版本                 |
| `POST /projects/:id/element-generation-previews` | 冻结范围与预算预览               |
| `GET/POST /projects/:id/element-generations`     | 历史与创建生成任务               |
| `GET /element-generations/:id`                   | 任务与候选详情                   |
| `GET /element-generations/:id/events`            | SSE 状态与阶段事件               |
| `POST /element-generations/:id/cancel`           | 取消后续执行                     |
| `POST /element-generations/:id/retry`            | 显式重试未完成阶段               |
| `PATCH /element-candidates/:id`                  | 按修订号保存作者改稿             |
| `POST /element-candidates/:id/regenerate`        | 保持身份重生成待审候选           |
| `POST /element-generations/:id/decisions`        | 带候选修订号与幂等键的接受或拒绝 |

正文与文档原有历史、恢复及 TXT 导出接口保留；导出仍只包含正文，不夹带要素资料。元数据总量继续受 64Ki 字符限制，候选过大时要求缩小内容。

## 验证与限制

本次逐项生成调整按主人要求仅做格式及编译构建检查，未执行测试。下述测试记录为此前实现阶段的记录。

已完成后端关键验证，包括八类管理、已确认版本选择、规划控制、无章节生成、依赖检查、事务回滚、幂等、字段锁定、单项重生成、取消与重试、来源版本和旧库迁移。相关写作/工作流/要素的 57 项后端用例通过。

浏览器检查已展示面板和字段表单；两个新增浏览器用例遇到定位器问题，已修正模型选择与相对字段定位。按主人要求停止追加和重跑测试，浏览器完整生成到接受流程尚未复验。最终类型与构建结果以本次交付说明为准。

模型请求仅使用离线适配器或本地 HTTP 模拟供应商，没有调用真实付费模型。结构和引用校验不能证明文学质量，人物动机、冲突吸引力与全书一致性仍需作者试读确认。首版关系为列表，时间为可读文本，不包含关系图、地图或拖拽时间轴。提取字段的语义真实性由作者核对，系统校验的是引用版本和片段范围。
