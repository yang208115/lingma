## 采用选择

- 编辑器采用受控原生 textarea，Markdown 为权威文本；不安装 CodeMirror。基础编辑由浏览器提供，选区使用 selectionStart/selectionEnd 的 UTF-16 半开区间，未连接 AI 执行。
- 版本比较采用 diff 9.0.0 的行差异；计算限制为 2000 编辑距离或约 100ms，超限退回完整并排文本，不隐藏任一侧内容。元数据按格式化 JSON 比较。
- schemaVersion=2，新增 `import_commits`，不修改已发布的 0001 迁移。确认导入的资源写入及响应账本同事务提交；重复确认检查规范化请求 hash，返回相同 documentIds 和结构版本。即使预览丢失、过期或进程重启，已提交结果仍可重查；请求不同返回 IDEMPOTENCY_CONFLICT。
- 导入同步生成预览，完成后才响应 ID；源文件和 manifest 原子发布到 `TEMP_DIR/novel-imports/<UUID>/`。预览不创建正式文档。未发布 manifest 的失败上传不可确认；已发布预览可跨正常重启读取，24 小时后拒绝确认，过期文件暂不自动删除。
- HTTP 使用 shared 的 P02 schema，所有业务事务共用 P01 的维护门闩；服务端持久化仍为单实例 SQLite，没有新账号或浏览器权威数据库。

## 数据与并发约束

`NovelService` 位于 `apps/server/src/services/novels.ts`，文档版本只新增、不覆盖。内容保存检查 baseVersionId，新增版本、更新当前指针、刷新作品更新时间在同一短事务完成；不持有跨网络事务。历史恢复复用相同保存过程，source=restore；已恢复之前的内容仍在历史中。

卷目录修改必须带 baseStructureVersion，提交完整卷列表及全部活跃文档的 ID/title/volumeId/sortOrder。漏项、重复 ID、外部作品引用被拒绝；删除文档通过独立端点处理。正文之外的资料不直接归卷。结构版本在新建/删除文档、作品改名及目录提交时递增，正文/元数据自动保存不改变目录版本。

章节软删除同时软删除其关联章纲，不物理删除历史版本。移除卷前将活跃章节移动到指定卷/未分卷，并解除已删除章节的该卷引用。章节暂不提供回收站/撤销删除界面，不自动清理历史；整部作品现已提供回收站与恢复入口。

作者可建立多份总纲或同一章的多份章纲；当前不强制单例，也不自动合并重复资料。标题和目录不计入正文历史；正文及人物等元数据才是当前不可变文档版本的内容。

## P05 可复用接口

| 接口                                            | 保证 / 边界                                                             |
| ----------------------------------------------- | ----------------------------------------------------------------------- |
| getProject(projectId) / getStructure(projectId) | 作品存在性、归属及一致结构快照                                          |
| getDocument(documentId)                         | 活跃文档与当前版本；已删除返回 NOT_FOUND                                |
| getVersion(documentId, versionId, projectId?)   | 版本必须属于文档；传 projectId 时同时检查作品；允许历史读取已软删除资料 |
| assertVersion(documentId, baseVersionId)        | 当前指针不匹配时抛 VERSION_CONFLICT，附 currentVersionId                |
| database.transaction(callback)                  | 多份资料创建冻结清单时由应用服务统一包装短事务                          |

以上仅提供资源/版本一致性基础，**不代替 P05 的运行冻结清单和动作权限检查**。客户端展示的目录可能晚于最新正文版本，发起运行前须等待保存完成并复核实际版本。

## HTTP 接口

前缀 `/api/v1`；JSON 输入运行时校验，响应 `{data}`；列表 `{data,nextCursor}`，默认 50、上限 200。错误沿用统一 error/requestId；校验 400、归属/缺失 403/404、版本/幂等冲突 409，维护/存储故障 503。未知接口不会返回前端 HTML。

| 方法 / 路径                                  | 输入或用途                                                                    |
| -------------------------------------------- | ----------------------------------------------------------------------------- |
| GET /projects                                | cursor 为最后一个项目 UUID，按 id 升序稳定分页                                |
| POST /projects                               | title，201 返回作品                                                           |
| GET /projects/:id                            | 单作品                                                                        |
| PATCH /projects/:id                          | title、baseStructureVersion                                                   |
| GET /projects/:id/structure                  | project、volumes、documents（不含正文）                                       |
| PUT /projects/:id/structure                  | baseStructureVersion、volumes、documents；schema 见 novel.ts                  |
| POST /projects/:id/documents                 | baseStructureVersion、kind、title、volumeId?、chapterId?、content?、metadata? |
| GET /documents/:id                           | document、version                                                             |
| PUT /documents/:id                           | baseVersionId、content、metadata；返回新版本                                  |
| DELETE /documents/:id                        | baseVersionId、baseStructureVersion；软删除及关联章纲软删除                   |
| GET /documents/:id/versions                  | 版本摘要，版本号倒序，cursor 为上一页最末版本号                               |
| GET /documents/:id/versions/:versionId       | 指定不可变版本，校验所属文档                                                  |
| POST /documents/:id/restore                  | baseVersionId、restoreVersionId；恢复为新版本                                 |
| POST /projects/:id/imports                   | multipart file、encoding（默认 utf-8），201 返回预览                          |
| GET /projects/:id/imports/:importId          | 预览及可选已确认结果，检查所属作品和有效期                                    |
| POST /projects/:id/imports/:importId/confirm | baseStructureVersion、volumeId(null 或本作品卷)、chapters[{title,content}]    |
| GET /projects/:id/export.txt                 | 可选 chapterId（只限本作品正文）；UTF-8 附件，不包含资料与运行记录            |

导入和正文保存限制统一见 `packages/shared/src/novel.ts` 的 novelLimits；HTTP 请求体上限 12 MiB。导入确认章数必须为 1—1000；空正文有效，不静默丢弃。UTF-8/GB18030/Big5/UTF-16 LE 用 TextDecoder fatal 模式，替换符及 NUL 被拒绝；编码选择不自动猜测。

## 草稿保存与交互

`DraftStore` 独立于 React 界面，按文档 ID 缓存草稿与 Promise。每份文档最多一个请求在途；提交成功推进 baseVersionId，保存过程中发生的新输入在同一循环继续提交，不提前显示“已保存”。切章/切作品不销毁队列。网络失败保留内容，提示显式重试；失败结果不会更新本地基准版本。

冲突会停止循环，读取服务器版本，展示“最新服务器 → 本地草稿”的正文和元数据差异。作者可继续编辑草稿，明确采用服务器内容或以最新服务器版本为基准保存合并稿；若服务器再次修改则再次冲突，不自动覆盖。

sessionStorage 按标签页/文档保留未保存草稿及基准内容；刷新后扫描当前作品并恢复其他章节的待保存草稿。恢复时基准过时直接进入冲突；存储失败显示警告。离开页面存在草稿时使用浏览器 beforeunload 提示，关闭标签页后不保证恢复，不能代替备份。服务端保存始终是权威状态。

历史恢复和删除要求先处理当前草稿；删除正文还检查已打开关联章纲的草稿。界面导出先恢复并保存相关待保存文档，有冲突/失败则阻止下载；API 直接导出的是最新已提交内容。原生 dialog 负责焦点约束，阻止弹窗期间编辑背景文档。

## 本次验证

- Vitest：基础设施回归、各文档类型/元数据版本、跨作品归属、结构冲突、历史恢复、软删除、分页、P01 → P02 迁移与重开、编码/拆章保留、导入幂等及批次回滚、保存队列/冲突/恢复草稿。
- Chromium：编辑中继续输入并切章重开、双标签页冲突合并、失败草稿刷新重试、历史比较恢复、人物元数据与目录归卷、人工修正导入、导出前保存和其他章节草稿恢复。
- 其余检查：类型、lint/包边界、生产构建、浏览器产物隔离、进程启动/代理/重复实例/优雅关闭/重启；CI 配置加入浏览器验收，本次未远端执行。
- 样本为人工合成；不使用真实作品、不运行模型，也不据此声称对所有小说排版或编码都能自动识别。
