# 通用编排与流程画布实施

日期：2026-11-05。本文描述已实现行为；产品方向见[通用创作编排与助手入口设计](./通用创作编排与助手入口设计.md)，可靠性后续目标见[编排完善设计](./多Agent编排完善设计.md)。

## 在哪里配置、在哪里运行

1. 左侧“工作流模板”进入默认的**流程画布**，选模板或复制为新模板。
2. 添加策划、生成、审校、分析或修订节点；拖动调整位置，从输出圆点连到下个节点的输入圆点。点击节点，在右侧配置名称、阶段类型、Agent 发布版本、必需审校和上游节点。也可用侧栏下拉选择上游，提供键盘操作路径。
3. 画布支持缩放、平移、适应视图、缩略图、自动布局、选中连线删除和节点删除，并提供展开大画布、100% 缩放与当前比例显示；默认适应视图保留至少 72% 的缩放，长图通过平移浏览。窄屏把配置放到画布下方。“列表编辑”保留表单编辑方式。
4. 保存并发布后，在写作/大纲助手输入区的“执行方式”选择模板，选模型、输入要求并发送。世界观生成侧栏也可选择世界观模板。
5. 对话中的工作流卡显示进度、候选、审校与作者操作。确认后保存对应资料，原“协作写作”页继续提供作品历史与完整运行详情。

**实际执行在本机 Node 后端 `WorkflowService`**，画布和助手是编辑、启动、查看入口。所有节点共用 `WritingService` 的模型队列；并发仍为 1，活跃队列容量仍为 32。浏览器刷新不会丢掉已持久化的运行；服务重启后按既有恢复机制显式恢复，不自动重发模型请求。

## 连线与节点配置

使用 [React Flow](https://reactflow.dev/learn) 实现交互画布。React Flow 负责拖拽、连接、缩放等界面行为，调度仍由项目已有的确定性编排器完成。

模板节点新增可选字段：

```ts
{
  key: 'review',
  name: '一致性检查',
  stage: 'review',
  agentVersionId: '已发布角色版本 ID',
  required: true,
  dependsOn: ['generate'],
  position: { x: 600, y: 80 }
}
```

- `dependsOn` 是执行依赖，`position` 只决定画布位置。拖动不改变逻辑；连线改变依赖。
- 旧模板省略 `dependsOn` 时普通节点按阶段顺序派生，连续审校共同依赖前面的非审校节点，表达其各自消费同一候选的既有行为；物理调用顺序仍保持串行。显式 `dependsOn` 仍严格按用户连线处理；`[]` 明确表示从创作输入开始。编辑连线时将全部依赖显式化，避免未连接的节点意外重新接回顺序链。
- 创建运行时按依赖拓扑排序，再依次执行。分叉可表达多个审校共享同一生成结果；物理执行继续串行。节点只消费其上游可达的最新策划、当前候选和分析，不注入独立分支的分析；审校仍不消费同轮其他审校报告。
- 发布校验节点 ID、引用存在、重复连线、自环和循环。多个生成节点必须组成一条内容链，策划须位于生成上游，每个审校须接到最终生成结果下游，至少一个审校必需。最多 16 个模板节点、一个策划和一个修订节点。
- 修订是系统反馈策略。所有审校先汇入系统“审校汇总”；通过后才进入作者确认候选。有重要问题或必需项未覆盖时，虚线从汇总进入定向修订，再回到全部审校；关闭自动修订或缺少修订节点时进入“等待作者处理”。系统汇总仅表达后端已有判断，不增加模型调用。不能手工把反馈回路变成普通依赖。自动修订开关仍生效。开始/候选结果是系统边界，不能删除或改接。
- 候选不变且复审仍有重要问题时，暂停等待作者处理，避免重复空转；没有新增轮数或调用限额。

本版没有条件表达式、任意脚本、HTTP 工具节点、跨作品输入、多个并行候选的合并语义或任意节点重跑。画布不是完整 Dify 平台复刻。

## 通用任务与保存

新增 `generate` 能力。模板和输入通过 `taskType` 区分用途；旧请求缺省为 `chapter_write`。

| 用途 | 输出类型 | 接受结果 |
| --- | --- | --- |
| `chapter_write` 正文 | `chapter_draft` | 旧有章节仍经 proposal 接受；无目标时按标题新建章节 |
| `worldbuilding` 世界观 | `element_candidates` | 新建/修改世界观条目，保留锁定字段，支持按条目接受 |
| `master_outline` 总纲 | `master_outline_candidate` | 新建或修改总纲 |
| `story_events` 事件规划 | `outline_event_batch` | 批量新建事件，或修改单个已有事件 |

内置新增世界观构建与审校、故事总纲规划、故事事件规划三套已发布模板与匹配角色。生成、审校、修订输出均受任务类型校验，正文 payload 不能冒充世界观。

`targetDocumentId` / `baseVersionId` 可同时为空，创建世界观、总纲或事件不要求章节。已有目标必须同作品、类型匹配、未归档且基准有效。写作助手按当前文档类型匹配目标：世界观模板不会把打开的正文章节当作保存对象；目标类型不匹配时创建新对象。当前助手尚无单独的“新建/修改”目标选择控件。

助手会话关联 `sessionId`；会话历史计数、预览和搜索纳入工作流。父工作流持有作品写作占用，助手不能另起与之冲突的写作任务；删除仍持有工作流的会话会被阻止。

## API 与迁移

沿用 `/api/v1/workflow-templates`、`/workflow-previews`、`/workflows`、`/workflows/:id/events`、`/workflows/:id/decisions`：

- 输入增加 `taskType`、`sessionId`、可空目标/基准，以及 `mode=create|fill|replace|extract`。
- `GET /workflows?projectId=…&sessionId=…` 返回当前会话历史；不传 `sessionId` 仍是作品历史。
- `accept_result` 接受通用候选，可用 `itemIds` 选择世界观条目。已接受条目记录在 `acceptedResults`；剩余条目可继续接受。跨条目临时关联必须先接受其依赖，或一起接受，随后解析为真实文档 ID。
- `edit_candidate` 可提交类型化 `payload`；编辑后新建候选并重新审校。已部分保存的批次不允许再编辑整体候选。
- 接受在事务内完成权限、基准和引用校验及业务文档保存，配合 `expectedRevision` 和 `Idempotency-Key` 防止重复点击重复写入。旧章节的接受接口保持兼容。

新增迁移 `0018-workflow-session-history.sql`，为父运行 JSON 中的会话字段建立历史索引。旧迁移不变，模板连线、位置及通用运行状态沿用现有 JSON 持久化，不需要另建图数据库。启动自动升级；不提供数据库降级。

## 验证与剩余范围

本轮覆盖服务端通用生成、无章节创建、目标隔离、字段锁定、来源基准、条目关联/部分接受、会话恢复与幂等，以及无序数组按图执行、独立分析输入隔离、循环/断链/独立内容分支拒绝。浏览器验证包括模板编辑、画布拖拽与真实连线、刷新恢复，以及助手内世界观、总纲和事件保存，不修改打开的正文。

模型验证使用本地模拟供应商，尚未验证真实模型稳定性与费用。完整可靠性设计中的独立审校批次、跨轮问题生命周期、依赖失效传播、任意节点重跑及资料/执行配置快照拆分仍未实现。资料刷新仍可能读取最新模型与全局提示词；本次没有把整份未来设计标为交付。
