# 通用编排与流程画布实施

整理日期：2026-11-10。本文合并角色库、通用任务与画布的现行使用和接口说明。Markdown 产物与作者闸门的设计依据见[编排重设计](./多Agent编排重设计.md)，自由图与内嵌辩论见[自由 Agent 图与多轮辩论](./自由Agent图与多轮辩论.md)。接口字段以 `packages/shared/src/workflows.ts` 和 `apps/server/src/http/workflows.ts` 为准。

## 配置与运行入口

1. 左侧“Agent 角色库”创建或复制角色，配置提示词、模型、Skill 版本、工具和资料偏好。角色保存草稿后可试运行，发布版本后供模板引用；支持归档和查看历史版本。
2. 在“工作流模板”通过 React Flow 画布添加节点、拖动位置、连接依赖并配置角色及自动/手动放行。保存草稿后发布，运行绑定具体发布版本。
3. 在作品写作、大纲或基本信息助手的“执行方式”选择模板，填写要求、选择模型与资料后发送。基础信息页提供整套基础信息或当前分类/条目的范围选择。
4. 助手运行卡显示进度、各节点返回内容与待处理操作。可查看完整产物和运行详情、编辑、重跑、放行及逐条采纳审校意见。启动时可选“全部手动放行”。
5. 最终候选经作者采用后才保存。旧 `/projects/:projectId/workflows` 链接跳转到写作页并定位对应运行及会话，已无独立协作写作页面。

角色草稿试运行冻结已保存配置，不发布角色版本，也不修改正式正文。内置角色与模板是可复用预设，不限制作者定义角色名称与数量。

## 两种执行方式

| 方式 | 行为 |
| --- | --- |
| 审校流程 | 策划、生成、分析和独立审校按连线执行，系统合并审校意见，按采纳结果修订并复审，最后等待作者接受 |
| 自由 Agent 图（`executionMode: "graph"`） | 任意已发布 Agent 按本轮依赖与上一轮反馈交流，可配置收尾汇总和最终输出；讨论用途只保留运行记录 |

审校流程也可以添加一整个多 Agent 辩论节点，作为上游材料与下游审校之间的子流程。具体配置、轮次与输入规则见[辩论说明](./自由Agent图与多轮辩论.md)。逻辑分支共用模型队列，实际供应商调用依次执行。

## 连线、闸门与产物

- `dependsOn` 是本轮依赖，`position` 只控制画布位置。普通依赖需通过引用存在、重复、自环及循环校验；审校流程还检查生成链与审校位置。自由图的跨轮反馈使用 `feedbackFrom`，不能构成同轮死循环。
- 节点最终 Markdown 回复直接保存为产物，不再通过 JSON 提交工具或字段补全循环。编排节点只提供被授权的读取类工具：`read_document`、`search_documents`、`load_skill`、`read_skill_file`。
- 每份产物保存节点、轮次、尝试、内容 hash、输入产物 ID、创建者及替代关系；作者编辑形成新产物，旧产物保留，相关下游结果失效并按依赖重跑。
- 手动节点完成后停在 `awaiting_gate`，作者可以查看、编辑、补充意见、放行或重跑。自动放行不会代替最终接受操作。
- 审校约定使用 `### [P0]`、`### [P1]`、`### [P2]` 标题和稿件引文。无法解析时保留整段为未结构化意见，不自动重试；未找到引文只提示未定位。
- 系统 `merge` 节点汇总意见并保留来源。作者逐条采纳或忽略，忽略 P0 必须填写理由；自动采纳默认处理 P0/P1，P2 留作建议。
- 自动修订开启时，只处理被采纳意见，随后按新一轮审校。修订内容与上一稿完全相同则停在 `NO_CHANGE`，等待作者处理。审校修订不设置固定轮数或调用次数上限；自由图的讨论轮数单独配置。

运行等待原因使用 `GATE`、`ADOPT`、`NO_CHANGE`、`RESULT` 区分。状态和原因用于展示，操作仍由服务端检查当前修订号、运行状态和权限。

## 通用任务与保存

| `taskType` | 结果用途 | 作者采用后的写入 |
| --- | --- | --- |
| `chapter_write` | 正文 | 已有章节通过提议新增版本；无目标时新建章节，可关联来源规划 |
| `basic_information` | 五类基础信息 | 按分类或条目保存故事定位、世界与场景、人物、核心冲突和叙事文风 |
| `worldbuilding` | 世界观条目 | 新建或修改世界观资料 |
| `master_outline` | 故事总纲 | 新建或修改总纲 |
| `story_events` | 事件规划 | 批量创建事件或修改已有事件 |
| `discussion` | 讨论/辩论 | 结论保存在运行记录，不写正式小说资料 |

基础信息、世界观与事件批次按 `## [分类] 标题` 拆条，再转换为保存适配器使用的类型化候选。模型输出仍是 Markdown，保存阶段负责分类、字段、目标、引用、锁定和版本校验。

基础信息通过 `elementKinds` 指定范围，未传时为五类；通过 `elementTargets: { documentId, baseVersionId }[]` 冻结已有条目。单次最多 30 个目标与 30 个候选，条目较多时分次处理。默认只补缺项，保留已有设定与锁定字段。

缺少分类时展示 `resultWarnings`，由作者选择“重跑缺失分类”（`rerun_missing`）；不自动触发模型补全。无法分类的输出保留供作者检查，不能绕过保存校验直接写入资料。

基础信息、世界观、总纲与事件任务不要求已有章节；已有目标必须属于当前作品、类型匹配且基准有效。无目标的正文生成也先形成候选，作者采用时才创建章节。

`accept_result` 可通过 `itemIds` 逐条采用，已采用结果保存在 `acceptedResults`。跨条目临时关联需先采用其依赖或一并采用。部分采用不会把本次保存本身误判为外部冲突；后续人工修改仍受版本保护。已部分采用的批次不能整体编辑或刷新资料，多目标基准变化时需重新运行。

## 快照、调度与恢复

每次运行冻结模板、角色版本、模型、参数、提示词、Skill 和授权资料。接口地址与密钥引用不进入工作流快照，各节点启动、恢复和重试时按绑定的模型配置读取当前连接信息；旧快照中的地址与密钥引用在读取时丢弃。角色或模板后续发布不影响已有流程；工具与资料权限取配置及授权范围的交集，不能跨作品访问或直接写正式内容。

所有节点与角色试运行复用 `WritingService` 的全局执行队列，同时执行 1 个模型任务，活跃队列最多 32。同一作品的活跃工作流持有写作占用，等待闸门、暂停、中断及可重试失败仍持有；普通写作与子运行通过同一占用规则协调。作者可结束并释放作品，人工编辑仍可进行。

关闭浏览器不取消后台任务。服务重启后遗留任务标记中断，不自动重新请求模型；作者恢复时先认领已完成子运行，再从完整轮次检查点重试。新尝试保留历史与用量，崩溃时远端是否计费可能未知，不承诺远端恰好调用一次。

引用资料变化时可明确沿用快照，或在允许状态下刷新资料并复审。刷新仅更新授权资料，保留冻结模型、参数、工具和全局提示词；目标正文变化时须先提供作者合并后的完整稿。自由图及含内嵌辩论的运行保留启动快照，需要最新资料时新建流程。

取消先关闭父流程推进资格，再取消排队和进行中的请求；迟到结果不发布给下游。作者决策和接受结果通过 `expectedRevision` 与 `Idempotency-Key` 控制竞态及重复写入，最终保存与业务版本检查在事务内完成。

## HTTP 接口

前缀 `/api/v1`。创建、发布、试运行、工作流创建、刷新资料及决策使用 `Idempotency-Key`；草稿修改和作者决策使用 `expectedRevision`。

| 接口 | 用途 |
| --- | --- |
| `GET /agent-capabilities` | 能力类型 |
| `GET/POST /agent-profiles` | 角色列表与创建 |
| `GET /agent-profiles/:id` | 草稿、归档状态与版本 |
| `PATCH /agent-profiles/:id/draft` | 保存角色草稿 |
| `POST /agent-profiles/:id/versions` | 发布角色 |
| `POST /agent-profiles/:id/archive` | 设置归档状态 |
| `POST /agent-profiles/:id/test-runs` | 未发布角色试运行 |
| `GET /agent-test-runs/:id` | 试运行详情 |
| `GET/POST /workflow-templates` | 模板列表与创建 |
| `PATCH /workflow-templates/:id/draft` | 保存模板草稿 |
| `POST /workflow-templates/:id/versions` | 校验并发布模板 |
| `POST /workflow-previews` | 资料、角色与上下文预览 |
| `POST /workflows` | 创建运行 |
| `GET /workflows?projectId=…&sessionId=…` | 作品或当前会话历史 |
| `GET /workflows/:id` | 完整状态、节点、产物、问题与用量 |
| `POST /workflows/:id/decisions` | 放行、重跑、编辑、采纳、暂停、恢复、取消与采用结果 |
| `POST /workflows/:id/refresh-sources` | 刷新授权资料及目标基准 |
| `GET /workflows/:id/events` | SSE；支持 `Last-Event-ID` 重放及 `check=1` 游标检查 |

决策动作包括 `release`、`rerun`、`edit_artifact`、`set_adoption`、`rerun_missing`、`continue`、`use_candidate`、`retry`、`resume`、`pause`、`cancel`、`reject`、`use_snapshot`、`accept_result`，以 shared schema 为准。没有独立的 pause/resume HTTP 端点。

父工作流 SSE 使用 `change` 事件，子运行的文本、思考和工具详情沿用 run API；前端断线后补读快照并恢复订阅。已有正文的最终提议沿用 `/proposals/:id/accept` 和 `/reject`，同步工作流结果。

## 持久化与迁移

- `0008-workflows.sql`：角色、模板及版本、父运行、节点尝试、产物、事件与决策。
- `0009-agent-trial-versions.sql`：未发布角色草稿试运行。
- `0018-workflow-session-history.sql`：助手会话中的工作流历史索引。
- `0020-workflow-reset.sql`：编排重设计时清理旧模板与工作流记录，保留角色、模型配置、业务文档及其历史。

图配置与运行状态沿用 JSON 快照，不另建图数据库；自由图和辩论不新增迁移。启动补齐缺失的内置模板，不覆盖作者已有模板。已应用迁移不允许改写，数据操作见[运行与数据维护](./运行与数据维护.md)。

## 验证入口与限制

`apps/server/test/workflows.test.ts` 覆盖版本冻结、图依赖、闸门、编辑失效、审校采纳、修订、资料刷新、保存、取消和恢复等行为；`e2e/workflows.spec.ts` 覆盖模板画布与助手运行路径。测试使用模拟模型；历史执行结果不代表当前改动已运行这些测试。

当前按节点运行卡与编辑区预览展示产物，独立整页产物界面仍是设计目标。条件脚本、跨作品输入、任意外部工具和整书连续自动写作未交付。其他工程和验证缺口统一记录于[待办与限制](./待办与限制.md)。
