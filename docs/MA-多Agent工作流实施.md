## 使用方式

从左侧导航打开“Agent 角色库”“工作流模板”，或选择作品进入“协作写作”独立页面：

1. **Agent 角色库**：从空白创建或复制预设；配置能力、提示词、独立模型或继承默认模型、Skill 版本、工具、资料类型偏好。先保存草稿，可对当前章节试运行；发布后供模板选用。支持归档和查看历史版本。
2. **工作流模板**：选择或复制默认模板，添加、移除和调整阶段，为每个阶段选择能力匹配的 Agent 发布版本。支持多个正文或润色节点、多个审校节点、独立修订角色及辅助分析节点。保存并发布模板后用于新任务。
3. **协作写作**：选定正文章节，填写创作要求、模型和模板版本，选择允许资料及固定全文；保存草稿并预览后启动。章纲可人工确认，可启用自动修订并复审，直到重要问题解决，再由作者接受最终稿。

作者编辑候选后，流程会重新审校新稿。正文或其他引用资料变化时，界面展示变化资料；可明确沿用冻结资料，或刷新资料并复审。正文基准变化时，刷新前须填写作者合并后的完整稿。任何接受操作都检查当前正文基准。

## 配置与执行契约

角色身份与能力类型分开：名称和数量由用户决定，能力限定为 `plan`、`draft`、`review`、`analysis`，对应固定的产物结构。自定义审校领域使用同一 `review_report` 结构，不增加角色名称枚举。

角色与模板采用草稿、revision 乐观锁和不可变发布版本。模板绑定具体 Agent 版本。每次运行冻结模板、角色、模型参数、提示词、Skill 及授权资料；修改角色或发布新版本不影响已有流程。归档角色保留历史和已有运行，新流程需替换已归档角色。

新增 `submit_workflow_artifact` 固定动作。动作产物先暂存，随完整轮次提交变为 committed；节点整体正常结束后，编排器发布产物并启动下游。截断、失败或无效产物不能成为正式提议。全流程最多自动修复一次缺失结构化产物的问题，其他失败由作者显式重试。

审校报告绑定具体稿件 ID，问题要求给出稿件原句；P0 必须提供授权资料引用或明确的作者要求引用 `author`。系统校验引用归属和范围，不把这些结构检查当作文学质量或事实语义正确性的证明。多个审校者的首轮输入不包含其他审校报告。

第一版按阶段顺序生成依赖：正文或润色节点读取上一稿；审校读取同一份最终初稿；修订读取问题集合；辅助产物向后续节点提供。输入映射与分支规则由内置阶段结构生成，当前未提供任意依赖图或脚本表达式编辑器。

## 持久化与运行控制

新增迁移：

- `0008-workflows.sql`：角色、模板及发布版本、父工作流、节点尝试、产物、事件和作者决策。
- `0009-agent-trial-versions.sql`：支持未发布角色草稿的试运行；工作流节点保留 Agent 发布版本外键，草稿测试将完整配置冻结在尝试记录内。

本功能迁移推进至 schemaVersion=9，不代表整个项目当前迁移版本。已应用迁移的 SQL 与 checksum 保持不变；项目当前版本见 README 与实际迁移清单。

工作流状态和节点清单保存在 `workflow_runs.state_json`，节点尝试单独关联既有 `runs`；没有新增独立的模型执行队列。所有子运行及角色试运行共用原 `WritingService` 调度，保持全局模型执行并发 1、活跃运行队列上限 32。

同作品的活跃工作流由数据库唯一索引限制；普通写作和父工作流在同一数据库事务内检查占用，子运行携带父 owner。等待作者、暂停、中断及可重试的失败流程继续持有占用，作者可“结束并释放作品”。人工编辑不受该占用限制。

节点重试创建新 run；输入相同且存在完整工具轮次检查点时，复用检查点和已提交产物。进程重启后不自动调用模型；作者恢复时，已完成子运行先对账认领，未完成节点从安全检查点重试。远端请求是否已计费在崩溃时可能未知，不承诺远端恰好一次。

2026-11-04：角色和工作流不再设置轮次、模型调用次数、执行期限或角色独立输出上限。模型输出沿用选定模型配置，调用次数和执行时间仅用于统计。自动修订改为开关，启用后重要问题未解决则继续修订并复审，不再限制一次；未配置修订节点时交由作者处理。

旧角色和模板中的限额字段读取时丢弃；旧 maxRevisions=0 转为关闭自动修订，其余旧配置转为开启。无需修改数据库迁移或历史数据。Token 和费用继续记录，未知值不显示为零，不同币种分别展示。

资料刷新保存旧快照至 `sourceHistory`，复制完整候选为新产物，再执行审校；历史节点、原稿和旧报告均保留。最终提议复用现有幂等接受、版本检查及正式文档历史。

## HTTP 接口

前缀 `/api/v1`。创建与发布、试运行、工作流创建及决策使用 `Idempotency-Key`；配置修改和作者决策使用 `expectedRevision`。

| 接口                                    | 用途                                                       |
| --------------------------------------- | ---------------------------------------------------------- |
| `GET /agent-capabilities`               | 查询能力类型                                               |
| `GET/POST /agent-profiles`              | 列表、新建或复制角色                                       |
| `GET /agent-profiles/:id`               | 草稿、归档状态与发布历史                                   |
| `PATCH /agent-profiles/:id/draft`       | 保存角色草稿                                               |
| `POST /agent-profiles/:id/versions`     | 发布角色                                                   |
| `POST /agent-profiles/:id/archive`      | 设置归档状态                                               |
| `POST /agent-profiles/:id/test-runs`    | 冻结已保存草稿试运行，不发布版本、不提议写稿               |
| `GET /agent-test-runs/:id`              | 读取试运行及完整产物                                       |
| `GET/POST /workflow-templates`          | 列表、新建或复制模板                                       |
| `PATCH /workflow-templates/:id/draft`   | 保存阶段配置                                               |
| `POST /workflow-templates/:id/versions` | 校验并发布模板                                             |
| `POST /workflow-previews`               | 模型、资料、角色与上下文占用预览                           |
| `POST /workflows`                       | 按预览 hash 创建流程                                       |
| `GET /workflows?projectId=...`          | 最近 100 条作品工作流                                      |
| `GET /workflows/:id`                    | 当前状态、完整产物、问题及用量                             |
| `POST /workflows/:id/decisions`         | 确认章纲、反馈、沿用快照、暂停、恢复、取消、编辑候选或拒绝 |
| `POST /workflows/:id/refresh-sources`   | 更新资料及正文基准，保留合并稿并复审                       |
| `GET /workflows/:id/events`             | SSE，使用 Last-Event-ID 重放；`check=1` 检查游标           |

工作流 SSE 使用 `change` 事件承载带序号的状态事件；子运行的 Token、思考和工具详情沿用原 run API。界面同时提供断线重连与快照补读。最终提议沿用 `/proposals/:id/accept` 和 `/reject`，事务内同步工作流结局。

当前只读列表返回当前实例配置，没有账号隔离；运行范围仍为本机服务。角色不能注册任意代码或工具，不能绕过授权访问其他作品，也不能直接写正式正文。

## 编排边界与后续设计

当前模板为 2—16 个配置节点，最多一个策划和一个修订节点；至少一个必需审校。此配置大小约束不限制动态追加的修订与复审轮数。依赖由阶段顺序隐式生成，尚无通用依赖字段、任意节点重跑或完整的失效传播；正文编辑和资料刷新通过新候选及追加复审避免旧稿报告用于新稿。

当前节点上下文会带入全部已有辅助分析，审校结果按当前稿件 ID 筛选；尚无独立审校批次、跨轮问题生命周期、逐问题豁免或无有效变化检测。`use_candidate` 是作者对完整候选的显式选择，不代表系统已自动裁决每条问题。

普通恢复和重试沿用冻结输入；资料刷新会重新执行 preview，因此可能同时读取最新模型配置与全局提示词。将“刷新资料”与“升级执行配置”拆开属于后续改进，不能将当前刷新行为理解为只改变资料版本。

暂停、恢复、取消和重试均使用 `/workflows/:id/decisions` 的 action；没有独立 `/pause`、`/resume` 或任意节点 rerun 端点。启动参数中的 `expectedPreviewHash` 当前可选；将其收紧为必需校验也属于后续协议变更。

## 验证范围

新增后端集成测试覆盖自定义角色、能力兼容、版本冻结、审校隔离、修订复审、格式修复、试运行、超过原调用上限后继续执行、取消、检查点及重启对账、资料变化与作者合并、重复接受和正文冲突。

浏览器测试通过真实 pi-ai SDK 与本地 HTTP 模拟供应商，验证“新建自定义 Agent → 加入模板 → 预览执行 → 刷新后确认章纲 → 审校 → 接受入稿”，以及未发布角色的独立试运行。模拟供应商不产生真实模型费用；实际供应商的文学质量、延迟与费用仍需使用主人配置的模型评测。
