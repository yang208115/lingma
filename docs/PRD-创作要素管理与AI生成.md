## 1. 产品目标与现有基础

在每部作品中增加独立的“创作要素”面板，把故事为什么值得写、发生在哪里、由谁推动、为什么发生冲突，以及如何展开和叙述集中管理。作者可以选择一个分类，从一句灵感生成候选，或在已有作品上补全该分类的缺项。每次参考八类已填写设定。

生成结果先进入候选区，作者可以修改、选择和确认，确认后进入正式资料，供聊天、章纲策划、正文写作和审校引用。正式资料的含义是作者采用的版本；剧情规划仍然是规划，不能被当成正文已经发生的事实。

当前代码基础：

| 现有能力                                                             | 本次新增或调整                                     |
| -------------------------------------------------------------------- | -------------------------------------------------- |
| `chapter`、`master_outline`、`chapter_outline`、`character` 四类文档 | 扩展其余创作要素类型，保留人物和总纲原有文档身份   |
| 左侧目录与通用 Markdown 编辑器，人物元数据通过 JSON 编辑             | 专门的分类面板、条目卡片、可读表单和关联选择器     |
| 文档不可变版本、自动保存、差异与恢复                                 | 要素字段、状态、关联和锁定信息一起版本化           |
| 单 Agent、持久化运行、SSE、作者接受提议                              | 作品级批量要素候选、跨条目引用和确认入库           |
| 多 Agent 单章策划、写作和审校                                        | 已确认要素可进入各阶段上下文，不要求先运行单章流程 |

本方案替代主 PRD 中“暂不建立世界观、时间线、伏笔专用模块”的旧边界；原需求确认表保留历史回答。既有多 Agent 模板中的“创意到整书规划”仍属后续能力，本次一键生成只建立创作基础资料，不等于完成整书章节规划或正文。

## 2. 小说创作的八类要素

八类是管理框架，不是要求作者开写前填满的问卷。所有分类都可留空、手动创建或由 AI 补全；某题材不适用的字段可以隐藏。

| 分类             | 回答的问题                             | 主要管理内容                                                                   | 默认形态                     |
| ---------------- | -------------------------------------- | ------------------------------------------------------------------------------ | ---------------------------- |
| 故事定位与主题   | 这是什么故事，读者为什么想读？         | 题材、受众、核心卖点、一句话梗概、主题命题、情绪体验、篇幅目标                 | 一份作品定位                 |
| 世界观           | 故事发生在哪种环境，规则和代价是什么？ | 时代、地理、社会制度、文化、资源、能力或科技体系、限制与禁忌；地点、组织、物品 | 世界总设定与多个设定条目     |
| 人物与关系       | 谁想要什么，为什么这样行动？           | 主配角、欲望、动机、弱点、能力、秘密、成长弧线及人物关系                       | 多个人物卡，关系从人物中管理 |
| 核心冲突         | 谁和谁争什么，为什么不能轻易解决？     | 对立目标、稀缺资源、阻碍、失败代价、时限、升级机制、艰难抉择                   | 一条主冲突，可添加支线冲突   |
| 情节主线与结构   | 冲突如何发展，人物如何改变？           | 故事起点、诱发事件、阶段目标、主要转折、高潮、结局方向、分卷安排               | 沿用总纲，可有多条主支线     |
| 时间线与关键事件 | 什么在何时发生，因果顺序是什么？       | 绝对或相对时间、事件、参与人物、地点、前置事件、对应章节                       | 事件列表                     |
| 伏笔与悬念       | 读者何时发现问题，又何时得到答案？     | 埋设信息、表层解释、真实含义、预期回收、关联线索与章节                         | 伏笔卡与回收状态             |
| 叙事与文风       | 用谁的视角，以什么节奏和语言讲？       | 视角、时态、基调、节奏、对白偏好、描写尺度、禁用表达、参考片段                 | 一份作品叙事约束             |

前五类作为总览中优先展示的核心基础，后三类默认折叠摘要；八类都提供基础管理与生成能力。首版不要求关系图、地图或可拖拽时间轴。

### 2.1 世界观字段

世界观条目选择子类型：总设定、地点、组织、体系、物品或其他。只展示对应字段，日常现实题材无需填写能力等级。

| 字段组     | 字段建议                                       | 设计要求                                 |
| ---------- | ---------------------------------------------- | ---------------------------------------- |
| 基本信息   | 名称、子类型、一句话说明、标签                 | 区分同名地点或组织，使用稳定 ID 关联     |
| 背景与空间 | 时代、地域、环境、历史节点                     | 未知信息允许留空；幻想历法不强制转公历   |
| 社会与势力 | 制度、文化、资源分配、组织目标、势力关系       | 说明这些安排怎样影响人物选择             |
| 规则与边界 | 能力或科技规则、使用条件、代价、限制、禁止事项 | 规则需要可供写作检查，避免只有抽象形容词 |
| 剧情关联   | 关联人物、冲突、地点或事件                     | 从当前作品条目中选择，可查看反向引用     |

例如“回溯能力”要记录“最多回溯十分钟，每次失去一段记忆”，而不只写“强大且神秘”。

### 2.2 人物与关系字段

| 字段组     | 字段建议                                           | 设计要求                             |
| ---------- | -------------------------------------------------- | ------------------------------------ |
| 身份       | 姓名、别名、角色定位、年龄或年龄段、身份与阵营     | 别名参与检索；除名称外均可后补       |
| 外在表现   | 外貌要点、言行习惯、对白特征                       | 以可执行的写作提示为主               |
| 行动逻辑   | 外在目标、内在需要、动机、价值观、底线、恐惧或缺陷 | 区分“想得到什么”与“需要改变什么”     |
| 能力与经历 | 关键经历、能力、资源、限制、秘密                   | 秘密标记知情范围，避免所有人物都知道 |
| 成长与状态 | 起始状态、成长弧线、计划终点、当前状态及依据章节   | 规划与已发生状态分开记录             |
| 关系       | 目标人物、关系类型、双方诉求、矛盾、变化方向       | 支持有方向的关系，如单方面信任       |

人物面板与现有人物文档共用文档 ID、版本和内容，不复制一份“面板人物”。旧人物全文完整保留，可逐步补录结构化字段。

### 2.3 核心冲突字段

| 字段           | 说明                                                           |
| -------------- | -------------------------------------------------------------- |
| 名称与层级     | 主冲突、支线冲突、人物内在冲突；可关联上级冲突                 |
| 冲突主体       | 主角或主要推动者，以及人物、组织、制度、环境或自我等对立力量   |
| 双方目标       | 分别想得到什么；为什么现阶段不能同时达成                       |
| 争夺焦点       | 资源、权力、生存、真相、关系、价值选择等                       |
| 阻碍与持续原因 | 为什么不能靠一次解释、退出或轻易让步解决                       |
| 失败代价与时限 | 不行动或失败会失去什么；没有时限可明确写“无固定时限”           |
| 升级与抉择     | 冲突如何升级，主角最终要付出什么代价或做出什么选择             |
| 关联与进展     | 关联人物、世界规则、事件、主线及规划阶段；已发生进展附章节依据 |

示例：主角要公开灾变真相救人，管理机构为维持结界秩序封锁真相；公开会引发结界失稳，沉默则会让被隐瞒的居民错过撤离。冲突需要同时写出对立目标、规则限制与选择代价。

### 2.4 通用信息与状态

每条要素均有名称、摘要、标签、详细说明、关联条目、来源和版本。正文关联可标为“已发生依据”或“计划出现章节”，不混用。

- **采用状态**：草稿、已确认、已归档。AI 候选独立存放，不直接成为已确认条目。
- **内容性质**：世界规则、已发生事实、未来规划，可细化到字段或关系；作者确认未来规划后，它仍是未来规划。
- **来源**：手动、已有文档整理、AI 创作、正文提取，保存运行及实际引用版本。无正文依据的 AI 创作不得标为“正文提取”。
- **锁定**：作者可锁定整条或指定字段；AI 补全与重生成必须保留锁定内容。手动解锁后可继续编辑。
- **缺项提醒**：展示“未填写失败代价”等可操作提示，不以字段数量计算文学质量，也不阻止继续写作。

手动新建默认草稿，可显式确认；AI 候选点击“确认入库”后成为已确认条目。编辑已确认条目先保存为草稿新版本，界面提示再次确认，历史确认版本继续可查看；运行默认选择当前已确认版本，作者可显式选用最新草稿。

## 3. 专门的创作要素面板

### 3.1 入口与布局

作品工作区提供“写作 / 创作要素”切换，面板始终属于当前作品。打开面板不依赖选中正文，也不要求作品已有章节。返回写作时恢复原章节与光标位置，并沿用既有待保存草稿处理。

桌面布局示意：

```text
作品名    [写作] [创作要素]                 [新建要素]
┌────────────┬─────────────────────────┬──────────────────────┐
│ 总览       │ 世界观：搜索 / 状态 / 标签 │ 条目详情或候选对比     │
│ 定位与主题 │                         │ 名称、摘要、字段       │
│ 世界观     │ 名称 · 摘要 · 采用状态    │ 详细说明、关联、来源   │
│ 人物与关系 │ 待补字段 · 被引用数量     │ [锁定] [版本历史]      │
│ 核心冲突   │                         │ [AI 补全] [确认]       │
│ 情节主线   │ 点击条目查看、编辑        │                       │
│ 时间线     │                         │ 生成时显示任务进度     │
│ 伏笔悬念   │                         │ 完成后显示候选与差异   │
│ 叙事文风   │                         │ [修改] [接受] [拒绝]   │
└────────────┴─────────────────────────┴──────────────────────┘
```

窄屏依次展示分类、列表、详情，通过返回导航切换。长表单分组折叠；操作有文字标签和键盘焦点，不只靠颜色区分状态。

### 3.2 总览与日常管理

总览按八类展示已确认数量、草稿数量、待审候选及关键缺项；点击进入对应分类。空作品展示“一句话灵感”输入框和可选的题材、基调、篇幅偏好，作者也可直接选择自由创作。

分类列表支持搜索、标签和采用状态筛选。条目支持新建、编辑、复制、确认、归档、恢复归档、历史比较及恢复；被引用条目优先归档，保留历史与引用。表单直接编辑字段，补充说明使用 Markdown，作者无需编辑 JSON。

关联区展示“关联谁”和“被谁引用”，可跳转到人物、世界规则、冲突、主线或章节。删除关联不会删除目标。历史引用展示当时版本与目标当前状态，不能把归档资料默认为新任务上下文。

“整理已有资料”先让作者选择本作品文档，再提取字段为候选。原文保持可读，接受整理前展示字段来源与差异，不按标题关键词静默迁移或覆盖。

## 4. AI 逐项生成体验

### 4.1 入口与生成模式

| 操作         | 使用场景                     | 默认行为                                             |
| ------------ | ---------------------------- | ---------------------------------------------------- |
| 生成本类     | 只想完善世界观、人物等某一类 | 使用相关已确认资料，生成该分类候选                   |
| AI 补全      | 某条人物或冲突已经有部分内容 | 只补空字段，保留已填及锁定内容                       |
| 重新生成     | 对某条候选或已填内容不满意   | 作者指定范围与要求，生成替代候选，提供前后差异       |
| 整理已有资料 | 已有存稿或设定文档           | 基于选定资料提取；无依据内容列为待补或单独的创作建议 |

每次只生成所选的一个分类。生成范围和参考资料范围分开：参考资料固定包含八类中全部已填写的最新保存内容，不因本次分类不同而减少。结果仍需作者接受。

### 4.2 启动条件与默认设置

1. 已选择作品并配置可用模型后，填写灵感即可点击生成；灵感为空时按“自由创作”生成，并明确显示这一模式。没有章节或 Skill 也能开始。
2. 面板预先显示模型、生成范围、只补缺项开关、已有资料范围及预计调用上限；默认设置可直接启动，高级设置折叠。模型未配置时提供现有模型设置入口，保留已填灵感。
3. 自动使用本作品八类已填写要素的最新保存版本作为约束，包括已保存草稿；空白项跳过。首次使用已有正文时，先展示可勾选资料范围，不默认发送全部存稿。
4. 启动前先保存被采用的本地草稿，检查权限及预算并冻结输入；无法保存时保留输入并提示处理。沿用现有模型接入、Token/费用展示与全局队列。
5. 发起后停留在面板查看进度，可以切换条目或返回写作；刷新后能找回任务与候选。不会要求先创建一个空章节来容纳运行。

单次只选择一个分类：定位、世界观、主冲突、主线、文风默认各一条，人物默认三条、事件默认三条、伏笔默认两条；不再一次生成八类或十三条整套资料。高级设置可调整人物及支线数量；已有条目满足目标时复用，只展示新增或修改部分。实际输出上限按模型配置检查，不能生成无限设定或整书正文。

### 4.3 生成逻辑与约束

先形成故事定位及世界、人物、冲突的初稿，再对照三者修订，随后生成主线、事件、伏笔与文风，最后检查关联与矛盾。它们在创作上相互影响，执行上采用有限阶段，避免世界观等人物、人物又等冲突的循环等待。

- 已确认内容默认作为硬约束；缺项生成不得修改已有非空字段。作者明确选择替换时才能提出修改候选。
- 锁定字段由服务端比较和强制保留，不只依赖提示词。资料引用中的指令不能改变任务权限。
- 人物目标要能推动冲突；冲突必须受世界规则约束；主线转折应能追溯到人物行动和代价。
- 候选用临时 ID 相互引用，服务端校验分类、引用范围和关系完整性；显示名称不能代替 ID。
- 每条候选展示生成理由、来源、关联及待决问题。文学上的“不够吸引人”作为建议，引用不存在、类型错误等作为结构错误。
- 新创作允许虚构设定，统一标为 AI 创作；提取模式无法确定的部分保留“未知”，不补造成已有正文事实。
- 输出格式错误最多自动修复一次，计入调用上限；仍失败则保留诊断和已完整校验候选，不接受半截 JSON。
- 一轮输出不足时可以在剩余预算内分批完成，不静默截断字段。达到上限后标明缺失分类，作者可明确重试缺项。

首版采用确定的任务阶段与现有 Agent loop，不要求作者配置多个角色。后续可增加“设定策划”角色预设，但不是逐项生成的前置条件。

### 4.4 审阅、部分接受与批量入库

候选区按分类分组，标明新增、补全、替换或无变化。作者可逐条查看、编辑候选、重新生成选中项、拒绝，或勾选多条后批量确认。

- 新增条目展示全部内容；更新条目展示基准版本、当前正式版本与候选差异。
- 作者编辑候选后重新做结构与关联校验，不需要再调用模型才能接受。
- 接受存在依赖的条目时，列出必须一并接受的候选；作者可以纳入依赖、改为关联已有条目或取消本次接受。不能自动接受未勾选的人物，也不能留下指向未入库临时 ID 的关联。
- 一次批量接受在一个事务中校验并写入全部选中项；任意目标版本冲突或依赖无效时全部不写，返回明确问题。已保存正式内容和候选都保留。
- 新条目由服务端分配正式 ID，统一替换临时关联；重复点击接受返回已有结果，不创建重复人物或冲突。
- 接受后保留生成来源与历史，可从任务记录继续处理未接受候选。已接受候选的后续修改作为新的候选修订，不追改已入库版本。

### 4.5 失败、中断和并发

任务执行状态与审阅状态分开：执行可排队、生成中、完成、部分完成、失败、取消或中断；审阅可待审、部分接受、全部接受、全部拒绝或已处理。模型生成完成不等于全部候选已入库；已处理表示没有待审项，可能同时包含接受和拒绝。

取消停止后续调用，保留已经完整校验的候选；失败和重启中断后提供显式重试，保留旧尝试，提示可能产生新用量。重试从已完成阶段继续，冻结资料保持原样；若作者要求使用新设定，则建立新任务。

同一作品已有占用冲突的写作或工作流任务时，按现有调度规则排队或提示等待，不另开绕过限额的模型队列。生成期间作者仍可编辑正式资料，接受时以基准版本检查冲突。

## 5. 与写作及多 Agent 工作流联动

| 使用位置             | 使用方式                                                       |
| -------------------- | -------------------------------------------------------------- |
| 写作聊天与上下文预览 | 可选择八类已确认要素，展示采用版本、推荐理由和实际片段         |
| 章纲策划             | 默认推荐故事定位、相关人物、主冲突、总纲及相关事件             |
| 正文写作             | 推荐当前人物目标、世界规则、场景冲突和叙事约束                 |
| 一致性审校           | 对照世界限制、人物知情范围、已发生事件及伏笔状态，返回版本引用 |
| 叙事审校             | 参考主题、冲突推进、人物弧线与文风约束，区分事实矛盾与叙事建议 |

上下文仍由作者查看和调整，开始后冻结。人物秘密是否让当前视角知道、未来事件是否可用，分别标明；即使作者允许 AI 读取未来规划，也不能让正文中的角色提前知情。

草稿、未接受候选、归档条目默认不参与新运行；作者显式使用草稿或候选时，运行清单标明其性质与版本。面板中“允许使用规划”与现有 `allowFutureOutline` 的关系需要统一到共享契约，不能只在前端隐藏标签。

接受正文不会自动推进时间线、回收伏笔或修改人物状态。后续可从已接受章节提取更新候选，仍经作者确认。设定变化后，面板列出直接引用的规划和条目，提示作者检查；不声称自动发现全部间接影响。

## 6. 数据与接口设计建议

以下是实施方向，不是已经存在的 API。沿用当前全栈 TypeScript、SQLite、共享 Zod schema、文档版本与运行服务，不新增外部存储或模型 SDK。

### 6.1 文档与字段

| 面板分类         | 建议文档类型      | 与现有文档关系                  |
| ---------------- | ----------------- | ------------------------------- |
| 故事定位与主题   | `story_premise`   | 新增                            |
| 世界观           | `worldbuilding`   | 新增，元数据保存子类型          |
| 人物与关系       | `character`       | 复用                            |
| 核心冲突         | `core_conflict`   | 新增                            |
| 情节主线与结构   | `master_outline`  | 复用，章纲仍关联正文            |
| 时间线与关键事件 | `timeline_event`  | 新增                            |
| 伏笔与悬念       | `foreshadow`      | 新增                            |
| 叙事与文风       | `narrative_style` | 新增，作品资料与 Skill 方法分开 |

结构化字段保存到版本化元数据的带 schema 版本命名空间；Markdown `content` 保存补充说明与原有全文。一个字段只有一个权威值，AI 所见的结构化摘要从当前版本派生，不额外维护一份可独立编辑的镜像正文。

人物关系首版归属于发起方人物的版本化字段，反向引用由查询派生，避免双向编辑不同步。关联必须校验当前作品归属；历史运行继续读取冻结版本。正文依据保存文档及版本 ID、片段位置，规划章节单独保存关联类型。

要素的当前编辑版本与已确认版本需分别记录，确认指针必须属于该文档；恢复历史新增版本，恢复后的内容重新确认。旧人物与总纲迁移为可读的已确认基线，不自动猜字段、不改原文；未知旧元数据原样保留。补字段采用兼容 schema，不要求重写旧版本。

新增六个文档类型时同步调整共享枚举、数据库约束、文档服务、目录标签、上下文读取、Agent 资料类型权限及导出筛选。已有角色的资料权限不静默扩大；提供“启用创作要素资料”的显式升级入口，发布新角色版本后使用，旧运行维持原权限。

### 6.2 作品级生成对象

建议新增 `element_generation_jobs`、`element_generation_attempts` 和 `element_candidates`，分别管理作品级任务、冻结输入与阶段检查点、候选及其审阅状态；子模型运行复用 `runs` 和统一调度。

任务最少记录作品 ID、模式、灵感与偏好、选定资料版本、模型和提示词快照、生成范围、限额、状态、用量及事件游标。候选最少记录临时 ID、分类、结构化内容、说明、依赖、来源、目标文档与基准版本、修订号及接受结果。原始模型响应与作者改稿分别保留。

现有单目标提议负责更新已有文档；批量新增与接受由要素服务在事务中处理，沿用相同的版本检查与幂等约定。不能把一份混合八类的大文本塞进现有单章正文提议，假装完成结构化管理。

### 6.3 API 草案

以下路径均以 `/api/v1` 为前缀。

| 接口                                             | 职责                                                     |
| ------------------------------------------------ | -------------------------------------------------------- |
| `GET /projects/:id/elements`                     | 分类汇总、搜索、筛选及条目列表                           |
| 现有文档创建、保存、历史和恢复接口               | 扩展类型与元数据校验，复用已有文档生命周期               |
| `POST /documents/:id/element-confirmations`      | 以基准版本确认要素，更新已确认版本指针                   |
| `POST /projects/:id/element-generation-previews` | 校验配置、冻结范围、预算与输入摘要；可由一键启动内部调用 |
| `POST /projects/:id/element-generations`         | 以预览 hash 和幂等键创建任务，无章节要求                 |
| `GET /projects/:id/element-generations`          | 找回本作品历史任务及待审候选                             |
| `GET /element-generations/:id`                   | 任务进度、候选、来源和用量                               |
| `GET /element-generations/:id/events`            | 持久化 SSE，支持游标重放和断线补读                       |
| `POST /element-generations/:id/cancel`           | 取消执行，保留已完成候选                                 |
| `POST /element-generations/:id/retry`            | 显式重试失败或缺失阶段                                   |
| `PATCH /element-candidates/:id`                  | 按候选修订号保存作者改稿，拒绝更新已接受候选             |
| `POST /element-generations/:id/decisions`        | 接受或拒绝指定候选，接受时传候选修订号、目标基准与幂等键 |

所有读取与写入均检查实例访问权限和作品归属；客户端不能借候选引用跨作品资料。前端编辑发生变化后使旧预览失效，服务端再次核对快照与锁定约束。

## 7. 实施顺序与范围

文档阶段已确认，随后按主人要求实施八类基础管理与 AI 生成；实际交付和验证限制见 [实施说明](./ELM-创作要素实施.md)。以下保留实施分解。

| 阶段              | 内容                                                           | 阶段验收                                                     |
| ----------------- | -------------------------------------------------------------- | ------------------------------------------------------------ |
| E1 要素底座与面板 | 类型扩展、兼容迁移、八类模板、表单、关联、采用状态、历史       | 旧作品可读；世界观、人物、冲突可独立编辑和相互关联           |
| E2 AI 生成与审阅  | 作品级任务、分类/单项生成、只补缺项、锁定、候选编辑、事务入库  | 从一句话产生关联候选，无章节可运行，接受后形成正式要素       |
| E3 写作接入与验证 | 上下文选择、角色权限升级、规划与事实区分、SSE 找回、冲突和幂等 | 单 Agent 与多 Agent 使用已确认要素，候选与未来信息边界可检查 |

后续增强：人物关系图、地图、拖拽时间轴、可配置任意字段模板、跨作品设定库、整书分章规划和连续生成、接受章节后的自动更新建议。本轮不把这些增强作为基础面板的前置条件。

## 8. 验收清单

| 编号   | 场景                                  | 可检查的结果                                                                         |
| ------ | ------------------------------------- | ------------------------------------------------------------------------------------ |
| ELM-01 | 打开无章节作品                        | 能进入面板、手动建要素并启动 AI，不要求空章节                                        |
| ELM-02 | 管理八类资料                          | 八类均有模板、列表与详情；世界观、人物、核心冲突有专属字段                           |
| ELM-03 | 打开已有作品                          | 原人物和总纲全文、元数据、历史、文档 ID 均保留；无重复副本                           |
| ELM-04 | 填写一句灵感并点击生成                | 只产生所选分类的候选，实际输入包含八类全部已填写内容，空白项跳过，完成前不写正式资料 |
| ELM-05 | 未配置模型或预算不足                  | 保留输入并指出缺项；不发送必然失败的模型请求                                         |
| ELM-06 | 已有目标、锁定世界规则后补全          | 已填字段及锁定值不变；不兼容建议被识别并保留供作者处理                               |
| ELM-07 | 单类生成、单项补全或重生成            | 只产生授权范围的候选，原条目与未选分类不被覆盖                                       |
| ELM-08 | 改稿后接受部分关联候选                | 提示依赖；接受后正式 ID 引用有效，未选依赖不被静默接受                               |
| ELM-09 | 批量接受时一条目标被修改              | 整批不写入，指出冲突条目，保留作者新稿和全部候选                                     |
| ELM-10 | 连续点击或网络重试接受                | 返回相同接受结果，不重复创建条目或版本                                               |
| ELM-11 | 刷新、断线、取消或服务重启            | 能找回任务及完整候选，状态明确，已应用内容不重复执行                                 |
| ELM-12 | 提取模式遇到正文没有的信息            | 标为未知或单独的创作建议，引用指向实际版本，不伪称原文事实                           |
| ELM-13 | 章纲或正文运行采用要素                | 实际输入可查看来源版本；未确认候选和归档资料默认不进入                               |
| ELM-14 | 作者确认一个未来死亡事件              | 时间线仍显示未来规划；当前章节和角色知识不当作事件已发生                             |
| ELM-15 | 编辑已确认要素、恢复旧版本            | 保留原确认版本；当前改稿待确认，历史恢复新增版本                                     |
| ELM-16 | 归档人物或世界条目                    | 历史引用可读，新任务默认不使用，关联位置显示归档状态                                 |
| ELM-17 | 候选包含跨作品 ID、悬空引用或错误类型 | 服务端拒绝入库，指出原因，未产生部分正式写入                                         |
| ELM-18 | AI 输出超限、格式错误或一类生成失败   | 有限修复且计入用量；已完成候选保留，可单独重试缺项                                   |
| ELM-19 | 已有多 Agent 角色读取新增要素         | 提供明确的权限升级，新角色版本可读取；旧配置与旧运行不被偷偷扩大                     |

实现时用合成资料与模拟供应商验证权限、版本、生成协议及入库流程；真实模型对人物动机、冲突力度和设定连贯性的表现另用试读样本评估。结构校验通过不等于文学质量通过。
