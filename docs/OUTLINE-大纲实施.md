# 基本信息与大纲

## 页面入口

- 原「创作要素」入口、页面标题及相关提示统一改为「基本信息」，八类资料与原有数据保持兼容。
- 长篇默认按「基本信息 → 总纲 → 章纲 → 正文」推进，完成基本信息引导后先进入大纲页。顶部可切换「写作」「大纲」「基本信息」。短篇可以使用「写作」「大纲」，不新增基本信息引导。
- 当前视图写入 URL 的 `view` 参数，刷新时保留。

## 大纲管理

- 独立的大纲目录分为故事总纲、章节大纲，展示章纲数量及已经开始写作的数量。
- 总纲沿用 `master_outline`，因此基本信息里的「情节主线」也会显示在故事总纲中，同一份内容不复制存储。
- 章纲沿用 `chapter_outline`，可以先独立新建、编辑和排序，`chapterId` 为可空关联；也可以选择关联已有正文。
- 章纲按自身顺序展示，无需先创建正文章节。点击「开始写作」时保存当前章纲，在一个事务中创建同名空白正文并关联；新正文按章纲位置排序。再次点击打开同一正文，不重复创建，也不把章纲内容复制成小说正文。
- 删除正文只解除章纲关联，保留章纲内容和版本；可从原章纲重新开始写作。
- 大纲使用原编辑器，保留自动保存、恢复草稿、版本历史、差异比较、右键编辑及删除确认。大纲页提供专用「大纲管理」入口。
- 新总纲标记为未来规划，防止被当成已发生事实。已有资料不迁移、不重建。

## 卷章与大纲目录分开管理

- 写作页的「卷章管理」按未分卷、各卷分组展示正文，支持修改卷名、章节名、章节归属及卷内顺序；移除卷会把章节移至未分卷，保存后生效。
- 新建正文的「所属卷」可选择已有卷，或选择「按大纲创建卷」中以「第…卷」命名的未归档故事事件，也可直接新建并填写卷名。选择大纲分卷时预填标题；从已有正文新建章节时默认沿用当前卷。提交后在同一事务中创建卷与章节，同名卷复用，失败时不留下空卷；不直接改写大纲事件。
- 大纲页的「大纲管理」以故事总纲、章节大纲两个分类展示。章纲独立排序，尚未创建正文的章纲同样可以管理；总纲、正文及基本信息不参加章纲排序。
- 人物、世界观、冲突、伏笔等基本信息不再出现在目录编辑列表中。
- 排序只交换当前分组条目，其他资料保持相对顺序。提交时保留完整文档集合，符合现有目录接口约束，不会因隐藏基本信息而将其移除。
- 弹窗独立滚动列表，标题与保存操作固定；边界条目的上移、下移按钮禁用。重新载入会同时更新编辑快照和版本号，失败时保留当前修改。

## 数据兼容

- 新增 `0013-outline-first.sql`，仅放宽章纲的非空正文关联约束，保留原 ID、内容、版本、索引、已有关联及外键检查，不修改旧迁移文件。
- 新增 `POST /api/v1/documents/:id/start-writing`，以章纲版本和目录版本防止过时创建。关联判断、正文创建与链接更新在同一事务中完成，并发及失败后的重复请求会复用已关联正文。
- 接口与共享 schema 都允许独立章纲；非章纲文档仍不能设置 `chapterId`，已有正文关联仍校验作品归属。
- 未关联正文的章纲作为未来规划，在普通正文写作中继续受「允许未来规划」设置约束；大纲助手允许读取这些规划。创建正文后，当前章关联章纲按原有上下文规则参与写作。

## AI 大纲助手

- 大纲页右侧使用现有助手，任务固定为大纲规划，允许读取未来规划，并授权创建章纲候选或为当前大纲建立修改提议。没有选中文档时也能创建章纲。
- 新增 `propose_master_outline` 工具，提交标题、完整总纲、生成理由和引用。仅在 `allowOutlineCreation` 授权的大纲规划任务提供；即使尚无总纲、未选中文档或当前选中故事事件，也能生成独立总纲候选。生成总纲、拆分事件和修改当前大纲分别使用各自的工具。
- 故事总纲目录提供「AI 生成总纲」入口，将总纲生成要求填入对话框并聚焦。候选支持展开 Markdown 预览，作者点击「保存故事总纲」后创建 `master_outline` 并打开。总纲保留未来规划标记，确认版本可供后续写作引用；现有总纲与正文保持原样。
- 总纲候选复用大纲候选表和确认接口，通过 `payload.kind` 区分总纲和事件。旧候选缺少该字段时按 `chapter_outline` 读取，无需数据库迁移；总纲候选仅允许一份，重复工具调用或重复确认不会重复创建。
- 章节大纲目录提供「AI 创建章纲」入口，将创建要求填入对话框并聚焦，作者可以修改章节数量等要求后发送；也可以直接输入「根据总纲创建前 5 章章纲」。
- 新增 `propose_chapter_outlines` 工具，一次提交 1–30 份按章节顺序排列的标题和完整纲要，围绕目标、冲突、关键事件、转折与悬念展开。仅在作品内大纲规划任务显式授权 `allowOutlineCreation` 时提供；讨论时正常回答。
- 新增章纲以独立审阅卡片展示，可逐章展开 Markdown 内容，生成结束后确认创建或拒绝。确认后在同一事务中顺序加入目录，创建来源记录为 AI 提议，并打开第一份章纲；重复确认不会重复创建。候选不会自动覆盖已有大纲，也不会创建小说正文。
- 修改已有大纲仍使用 `propose_document_change`，只修改当前目标；创建多章时必须提交章纲候选，不能把多章内容写入当前总纲代替创建。
- 运行前保存作品草稿，将基本信息中已填写、未归档、未被用户排除的最新版本（包括已保存草稿）固定到上下文；未填写资料跳过。原上下文预算与固定资料数量限制继续生效，超限提示缩小范围，不静默截断。
- 已有大纲的修改候选在中央编辑区显示差异，由作者确认后保存为新版本，不自动覆盖。
- 正文助手的任务用途及资料权限保留原行为。切回写作页后恢复原用途选择。
- 新增迁移 `0014-outline-creation-proposals.sql` 保存章纲候选、所属运行和接受结果；候选随完整回合提交后才可审阅，中断回合的暂存候选作废。后端重新载入时应用迁移。

## AI 新建章节与输入引用

- 写作与聊天任务提供 `propose_chapter_creation` 工具，AI 可自行拟定标题、选择已有卷或填写新卷名称，并按要求提交空白章节或完整正文；可关联当前允许的故事事件。候选预览显示标题、所属卷、关联数量和正文，确认后在同一事务中创建章节、卷及关联，并打开正文。重复确认复用创建结果。
- 新章候选复用现有候选表和审阅接口，以 `payload.kind = chapter` 区分。生成期间不可确认，中断回合暂存内容作废；关联事件发生修改、删除或归档时拒绝过时关联。章节工具需作品内显式授权 `allowChapterCreation`，大纲规划、选区改写、Skill 实验和协作节点不自动获得该权限。
- 当前没有正文目标时，写作助手直接生成新章候选，不再预先创建名为「新章节」的空正文。仅讨论时不会创建文档，原有正文的修改仍使用目标修改提议。
- 写作和大纲输入框输入 `@` 即可搜索卷、章节、大纲、人物及其他资料。支持点击、上下键、Enter/Tab 确认、Esc 关闭、引用标签移除和输入草稿恢复；同名资料使用独立标签并绑定真实 ID，正文可读范围仍遵循当前章节顺序。
- 发送时保存草稿、重新解析引用，并将文档当前版本固定到上下文。引用卷时提供卷目录，匹配的分卷事件一并固定；显式引用规划资料时允许相应规划参与。删除引用标签后不再携带该引用；资料已删除、归档、被排除或超出上下文预算时明确提示，不静默忽略。
- 聊天回复仅用于说明结果，移除「将候选转为提议」入口和前端调用。旧 `POST /runs/:id/proposals` 接口统一拒绝转换，旧幂等记录也不能恢复此入口；非协作流程中由聊天转换而来的历史待确认提议不可采纳。协作流程仍由结构化正文产物发布最终提议。
- 新建正文章节与修改已有文档在提交和确认两处均由服务端互斥控制，与调用先后顺序无关；重试检查祖先运行中已经提交的动作，中断回合已废弃的暂存内容不锁定动作。助手收到明确的错误信息，需要另一种操作时另发任务。
- 新章卡片始终显示「新建到：卷名」与章节标题，修改卡片显示「修改：目标文档名称」，分别使用「创建章节」与「采纳修改」。聊天文本区域标为「助手回复」。

## 助手展示与尺寸

- 助手回复、历史消息及章纲候选共用 Markdown 渲染器，启用 GFM 表格、删除线和任务列表支持。宽表格在内容区域内横向滚动，不撑开整个侧栏。
- Markdown 的普通单换行保留为可见换行。总纲、事件与大纲候选预览兼容历史内容中的字面量 `\n`、`\r\n`；新生成及采纳的大纲在保存前修正这些换行。代码块和行内代码中的转义保持原样，已有文档版本不直接改写。
- 写作页与大纲页均可拖动助手左侧分隔线调整宽度，保留正文的最小阅读宽度；调整结果按标签页保存，刷新后恢复。双击分隔线或聚焦后按 Enter 恢复默认，左右方向键微调，Shift 加速，Home/End 调到边界。
- 窄屏继续上下排列，隐藏横向分隔线。任务输入框保留原生纵向拖动，最大高度放宽至半屏或 480px，避免长提示词只能在很小的框内编辑。
